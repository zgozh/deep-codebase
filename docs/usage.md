# 使用指南

## 安装与发现

推荐 Skills CLI，根据所用 Agent 选择安装目标：

```bash
npx skills add zgozh/deep-codebase --skill deep-codebase-learning -g -a codex
```

`--skill` 指定本仓库中的 Skill，`-g` 表示用户级安装；`-a codex` 可限定 Codex，`-y` 可跳过安装器确认。省略 `-g` 则安装到当前项目。安装器支持的 Agent 和目录以 [其官方文档](https://github.com/vercel-labs/skills) 为准；本项目不声称所有 Agent 已经过行为测试。

本机HTTPS访问不可用、但已经配置GitHub SSH访问时，可使用完整SSH地址：

```bash
npx skills add git@github.com:zgozh/deep-codebase.git --skill deep-codebase-learning -g
```

SSH访问需要你的GitHub密钥权限；不要求把密钥或token写入Skill。无法使用SSH时也可下载仓库并从本地目录安装：`npx skills add ./deep-codebase --skill deep-codebase-learning -g`。

CLI 的安装目录由当前安装器和宿主发现规则决定；当前 Skills CLI 的 Codex 用户级目录是 `~/.agents/skills`，以 [安装器文档](https://github.com/vercel-labs/skills) 和实际发现结果为准。下面的 `~/.codex/skills` 是本项目历史实际使用过的手动目录，不是所有宿主/版本唯一通用的官方路径。没有 Node/npm 可复制整个 Skill 文件夹到宿主支持的目录；配置了 `CODEX_HOME` 时也核对该配置的发现规则。若出现两份安装，先确认会话加载哪一份，不自动删文件或搬目录。

### macOS / Linux 手动安装

确认目标不存在再运行；已有版本先查看下方更新说明。

```bash
git clone https://github.com/zgozh/deep-codebase.git
mkdir -p ~/.codex/skills
cp -R deep-codebase/deep-codebase-learning ~/.codex/skills/
```

### Windows PowerShell 手动安装

```powershell
git clone https://github.com/zgozh/deep-codebase.git
$skillRoot = Join-Path $env:USERPROFILE '.codex/skills'
$skillTarget = Join-Path $skillRoot 'deep-codebase-learning'
if (Test-Path -LiteralPath $skillTarget) { throw 'Existing skill: use the update instructions.' }
New-Item -ItemType Directory -Force -Path $skillRoot | Out-Null
Copy-Item -LiteralPath './deep-codebase/deep-codebase-learning' -Destination $skillTarget -Recurse
```

其他 Agent 使用其支持的 Skills 目录。复制文件夹时不要改名；`deep-codebase-learning` 必须与 frontmatter 的 name 相同，`references/` 和 `assets/` 需要一起复制。不要只复制 SKILL.md。

安装后在目标项目打开新会话。若 Agent 提供技能列表，确认包含 `deep-codebase-learning`；Codex 可显式调用 `$deep-codebase-learning`。本 Skill 自动发现默认开启，其他 Skill 同时匹配时显式调用有助于消除歧义。

## 第一次学习

打开真实源码项目而非 Skill 安装目录，说“带我深度学习这个项目”。可以顺带说背景，例如“我会基础 Java，但不熟悉 Spring”。不需要先填写长问卷。

需要宿主能读这个真实项目副本、写入 `.codelearn/`，并访问相关官方资料；不用先装目标应用依赖才能读源码。没有运行条件时照常静态教学，动态结果保持未验证；官方资料暂不可访问就说明未核实范围。完全没有编程经验可以直接说：

```text
使用 $deep-codebase-learning 带我从零深度学习当前项目。我没有编程经验，先讲项目做什么，并在第一次需要时解释路径、代码符号和命令怎么读。
```

导师会在当前文件旁解释项目根/当前目录、相对路径与扩展名、原源行、定义和调用、摘录省略范围，以及教学注释为何不用复制覆盖源文件；需要操作时说明实际系统/工具、工作目录、参数/占位值、输出位置与错误定位。已有证据减少重复，不用先学完通用电脑基础。默认已经详细，下面的偏好请求用于纠正遗漏，不是解锁深度的必需口令。

| 本次目标 | 合理边界 |
|---|---|
| 快速了解 | 有据讲项目问题、能力、分工和一条流程；不能宣布实现已掌握 |
| 深度学习 | 连续读真实注释源码，补当前基础，解释值/状态/返回/失败与设计 |
| 完整能力完成 | 全部实际分区 Inventory、横向审计、独立能力证据与可运行 Mini Version 通过后才 PROJECT_COMPLETE |

协议不绑定模型/档位，默认单会话；首次询问可选主会话规划审查、子 agent 编写，环境不支持或未选择仍单会话完成教材。现有 Luna max 样本不保证所有模型/项目表现；见 [验证范围](validation.md)。

Skill 始终默认完全初学者，不预设你懂术语、框架、语言、功能、架构和原理。模型主动给完整路线：“项目问题→能力→架构→代表功能/系统事件→渐进真实源码（有前后端则贯通）→其他能力→横向审计→验证与独立重建”。每课一个因果目标，当前必要基础充分解释，语言/框架前置先于依赖代码；小课限制广度，不限制详细输出，不等同一句释义。无需先上脱离项目的基础长课。

术语首次出现会解释，必要前置知识主动补齐，再回当前代码；你不必主动说“这个我不会”。已有学习记录中的独立能力证据保留，已掌握部分可加快或略过重复解释。初学者只是教学默认，不会被写成“你答错了”或清零掌握度。

Agent 识别项目根、定向扫描并建立 `.codelearn/`，首节详细笔记讲项目问题、能力、粗粒度架构与白话流程，再说明路线。首轮不出陌生知识题；模式询问不阻塞首节。大项目模块范围先建立，其余分区增量细化，未查内容 pending/unknown，不为第一课深挖所有支路。

你主要阅读 `.codelearn/notes/` 中的正式教材，聊天给范围与可点击路径，随时可问疑问。教材包含当前必要解释，不要求先看聊天、翻原源码或自行读官方资料。你可以自愿按准确定位看项目源码，但这不是补齐教材的义务。只有明确“在聊天完整讲一节”时才展开整课。内容质量、源码核对和个人能力始终分开。

## 选择编写模式

首次提供一次选择，已有明确偏好就沿用：

| 模式 | 工作方式 |
|---|---|
| 单会话（默认） | 当前模型规划、写完整教材、实际通读补缺并维护记忆；可 ready/self_review 正常交付，无需子 agent 或独审 |
| 主会话规划审查 + 子 agent 编写 | 主会话指定一节目标/前置/源范围，子 agent 只写独占草稿，主会话逐段核对、返修后统一交付与写状态 |

未答复不等于委派授权，保持单会话继续。选择保存当前 Stage 与 journal，跨阶段继承；可随时说“改回单会话”或“用主会话规划审查、子 agent 写教材”。不锁模型、无额外工具/服务要求，委派可能增加资源和耗时，不保证自动更好。不能让多个 agent 同时改 state/journal/索引/mastery；编写者与主审不同时编辑同稿。详情见 [编写模式协议](../deep-codebase-learning/references/authoring.md)。

多仓库工作区可明确“学习 `backend/` 和 `frontend/` 组成的系统”。若项目根无法判断，Agent 会只澄清这个必要信息。路径不可访问或写权限不足时会报告真实限制。

## 继续、提问与结束

可直接复制，不需要管理状态命令：

```text
继续学习，接着当前代码和因果问题讲。
这段仍太浅，请详细讲所有当前新概念、重要语句和官方资料，并保存这个偏好。
总结当前主题。
总结当前阶段。
总结当前会话。
先继续讲解，暂时不要让我作答；能力未验证照实保留。
先切到开发任务：修复这个问题，并保存学习返回点。
重新读取 $deep-codebase-learning 的最新 SKILL.md 和相关协议，保留当前进度继续学习。
```

可固定一个会话长期学；“继续学习”恢复最新偏好并实际编写下一节，有价值变化逐轮保存、每节教材直接落盘。上下文压缩按局部记忆恢复，不读全部历史，不等结束才整理。

恢复读当前阶段、正式教材范围、相关源码、近期事件/能力与返回点；计划/草稿不算已交付，交付不算用户掌握。最新交付偏好优先旧待答/历史聊天规则，不问上次位置，不强制重考。通常继续教材，用户愿意且前置实际就绪才测试。

随时可以问：“这一行是什么意思？”“为什么用 DTO？”“先直接解释，不要考我。”路线不会阻止即时问题。直接解释不构成独立掌握证据。

如果说“我不知道怎么回答”“一头雾水”“请从整体从零讲”，导师应暂停原题，回到缺失的全景/概念层级实际讲授；保留已有源码调查与笔记。不会只把完整复述题换成更小的字段题，也不将节奏反馈当成答错。已有局部路线可插入项目全景阶段，不删除历史。

题目针对充分解释的内容，提问时给必要片段/上下文，不能假定你已读过教材。不是每轮固定动作，也不阻塞阅读/继续交付；阶段能力 waiting 不等于失败。聊天局部问题直接解惑，足以解决当前问题，不自动扩成整课；发现实质遗漏/错误/歧义修对应教材/索引/受影响进度，只是即时澄清则不用重写。

“今天到这里”触发检查点，保留下一动作。即使会话突然结束，已执行的有意义交互应已保存；不能保证 Agent 在外部强制中断前尚未完成的文件写入。发生断写时下次先检查 pending 事件。

## 源码课应该交付什么

练习可按意愿逐步增加独立性：导师完整演示一次，再让你用已教的同类例子完成一个值/步骤或小修改，允许提示；就绪后再独立变式，更晚独立小实现。支持依据真实表现减少，带提示成功仍是 hinted，不算独立通过。没有作答也能继续授课，能力验收保持 waiting。具体非 Web 示例见 [CLI 小课](examples.md#k非-web-cli-零基础小课与可选练习)。

不用先列陌生词：当前需要的新概念、符号、导入 API 都先用白话、具体值和因果例子讲懂，再读真实代码。重要导入/定义、变量/参数、分支、调用、返回和副作用逐句注释，说明来源、消费者与必要机制；注释不写回项目文件，源行锚点仍对应原代码。定义/注册/稍后回调、同步/异步恢复、类型/运行清楚区分。同名概念以前只有名称或职责介绍，不默认机制已教；当前必要前置不能推到未来课。

可说“以后每课都非常详细，所有当前新概念、逐行解释和官方资料都带着讲”。这会变成持久偏好，后续课继续应用，不只临时拉长一轮。官方章节先核对当前相关版本/来源，导师实际读后解释含义、机制、源码映射、例子与限制，再链接；版本未确认明确未知，文档不是实际部署证明。

笔记就是正式完整教学，语法/名词/机制与源码解释紧邻；专业名词给准确名称/中文含义、缩写全称，不编项目名展开。重要导入、类型、参数、调用/返回/状态和副作用逐行或语义段讲明；贯穿输入到结果的示例，演算值与实测分开。官方文档实际读适用章节后消化到使用处，不列一排链接让读者拼接。完整教材实际通读补缺、V0/保存/索引后正式 delivered，single 可 ready/self_review；独审可选，validated 只用于真实独立审读范围，具体充分解释可记 explained。模型写出或用户读过都不会自动增加 mastery，包括 L1。

“继续深度学习项目”应按实际已教的阶段继续授课，不只是报下一批文件名。缺全景先补业务/能力/模块边界和白话流程；全景已教过则直接进入当前功能的小目标。

源码课在教材展示真实路径/符号/原行号或可靠定位，按顺序读当前关键实现；配置不能止于文件职责，要找到谁绑定/读取、何时生效、调用怎样改变，优先级/热更新未知就标未知。每篇一个因果目标，过长拆连续小课，标起止/未覆盖及下一符号问题；不为短删必要解释，不为长反复堆字。

你说“讲得太浅、我不懂”时，导师先修本课遗漏，不换成陌生字段题、不将漏讲记为你答错。发送前用具体值逐句推演，检查是否仍要猜词义、参数来源、框架时机或返回去向；有断点先改写，目标过大缩范围保深度。这是质量约束，不保证所有模型实际执行稳定。见 [协议](../deep-codebase-learning/references/teaching.md) 与 [三类完整示范和恢复场景](examples.md#jv150-详细教学验收示范)。

## 自动详细笔记的触发条件

Journal 保存结构化过程，教材保存完整知识，两者不同。默认每节直接产生正式详细笔记，而不是等聊天讲完才整理：

1. 一个因果目标的教材解释、真实注释代码、调用/状态、例子/重要失败和证据边界通过门禁，即保存/交付本节。不等用户说结束、不等 Quiz/Stage 通过。
2. 多个相关主题累积到自然边界或上下文紧张时，检查重要内容已写进主题笔记，更新阅读索引、未解项与下一动作。不按固定轮数重复输出整篇。
3. Stage 学习 Exit Criteria 通过时，综合各主题与跨主题关系，写详细 Stage Note，再做文章质量检查。两道门都通过才标完成。

Topic/Stage 还可自然收束综合关系；文章质量可合格，而用户独立能力仍待验证。小释义与简单 helper 并入已有文章，问答有实质增量补相应段落，不每轮重写整篇。

默认中文内容分类：`.codelearn/notes/S00-项目全景/`、`S01-登录与权限/` 等，名称根据真实阶段决定；课名如 `S01-T01-01-从输入到登录请求.md`，阶段综合 `S01-阶段总览.md`。中文 `notes/索引.md` 按阶段列入口/范围/事件/质量/未知与接续；会话整理在 `notes/会话/`。不用通用 `主题/` 堆全部文件。稳定 ID 保留，英文源码标识不翻译。旧路径按触及范围迁移，同步 Stage/state/journal/review/roadmap/知识/笔记互链，不能只改名留坏链接或覆盖已有目标。

作者尽早写一份完整可读初稿，再定点查证。返修先有实际可恢复的旧版本，局部补缺，保留原正确必要概念、语法/机制、源段/值链、为什么/例子和官方映射；删错/重复给依据，迁移须实际写好且本课必需解释仍在。不能将详细教材重写为摘要，也不能以 hash、篇幅或写作时长证明保留。

按 [作者流程](../deep-codebase-learning/references/authoring.md) 实际从头通读一次：single 作者自查，delegated 主会话自身独立读子稿。语法/概念/机制、真实源段/状态、正常与重要失败一起核，自己懂或能走值链不能补正文。缺口先修教材，只简记方法/范围、重要缺陷及处理/未核实项，不要逐段报表或教材双 hash。局部修后读影响链，广泛重写/源范围大变/影响不明才全文重读。必要 V0/保存后给主题范围链接；有价值互动/中断仍及时 checkpoint，不跑应用测试/构建/浏览器。

v1.11.2 按 [十章教材模板](../deep-codebase-learning/assets/templates/stage-note.md) 展开：实际业务使用→真实架构合作→必要概念→初始化/注册至可见结果的交接→完整源码精读→最难机制/官方规则→同值正常与重要失败→完整使用/修改教程和取舍→易混/带答案复习→收获/证据/下一课。路线按真实功能安排，章次/职责保留。多参与者功能给真实架构与时序/数据流图及逐段解释，全景/配置/脚本/测试按证据适配。同一次语义通读覆盖每章及每个行为单元全部适用任务；少数难点成功、全链正确或少量记录不能替代其余单元核查。源码/知识事实与教学展开分别判断，审读者自己的经验不补正文。当前示例已按职责与实际正文审读、返修并复读影响范围，可供试读；实际范围见 [验证记录](validation.md)，不宣称用户认可、应用运行或真实学习效果。

第五章是主体。按初始化和用户操作的因果次序教，必要定义在首次依赖处解释，不照文件定义顺序把入口留最后。每个行为单元用可定位的八个固定职责小节，标题可语境化：问题/思路、架构位置/触发/具体输入、定位/阅读准备、完整注释源码、逐行正文、同输入局部运行/重要失败、机制判断、用法/上下游/接入/修改影响。定位有完整路径、符号、原行范围、版本与可点击入口，私有源码不上传。不同问题的方法各有单元，重要方法短不豁免，纯声明/重复可合并并教消费者。源码前中后各负不同任务，后章与全链已教不豁免当前单元。

短示例不决定真实课源码规模。当前职责需要的完整方法/组件/配置读取，及必要真实调用、创建注册和消费者都须展示并讲清；长源码按连续原行分块保留全部相关语句与上下文，不删难行、不补造关闭结构。不强贴无关整文件或整仓，也没有片段行数/字数下限。返修重组受影响单元，不在末尾堆重复说明；保留正确源码和必要解释，去实质重复交代去向。

所有新名词首次先就地短释，第三章再按理解依赖写成连贯基础概念课，结合带值源码或明确标示的教学示意、实际操作、真实链路/框架和适用官方规则深入讲问题、机制、例子、易混与设计含义；第五章应用于当前代码，第六章深化系统机制，前文必需含义不延期，不把概念散成随口释义或术语百科。第六章从具体输入经项目调用、框架何时为何介入、实际运行步骤/状态到可见后果解释已读官方规则与限制，不只是 API 释义和链接。后四章须有实际值链、失败后果、受约束方案比较和完整答案。当前作者上下文首次完整课或重大反馈/重写先全文读 [完整示例](../deep-codebase-learning/references/quality-example.md)，之后复用已理解风格，不逐轮盲读或复制其技术事实。仍是一个完整稿、一次实际语义通读、定点修正文、V0与集中保存。

返修在同一 review 短记增/改/移/删的实际段落及原因，不按字数压缩。收尾按 [PERSIST一致性约定](../deep-codebase-learning/references/memory.md#post-turn-learning-commit) 对齐正文、索引和本次事件，保持当前学习位置；本轮使用版本与源码版本分开记录，问答/中断仍及时保存。

## 显式总结用法

不需要等待自动触发。下面这些自然语言请求已被定义，同义表达也适用：

| 表达 | 结果 |
|---|---|
| “总结当前主题”“详细总结刚才的内容” | 保存当前主题详细笔记；内容不足时写部分草稿与缺口 |
| “总结当前阶段” | 保存当前阶段文章；未验收仍可写草稿，列出必要复述/实验等缺项 |
| “总结当前会话” | 按可恢复的事件范围写 `notes/会话/` 文章；组织技术内容与个人认知，不复制原聊天 |
| “重新核对这份笔记” | 回到相关源码与学习证据检查关键事实、修订推断和核对状态 |
| “总结一下” | 默认最近正在讨论的主题，有明确指代时使用该范围 |

默认详细内容落盘，聊天里给简洁结论与链接。请求总结不会自动切换 Stage、提高 mastery 或清除 awaiting；写完自然返回原主线。你明确要求只在聊天中简短总结、不写文件时，尊重这个选择。

## 如何看待生成的笔记

自动和显式生成都默认是候选知识，首写 `status=draft`、`verification=unverified`。核对后分别记录：

- `status=ready`：完整稿实际通读补缺后可正式交付，single 记 `review_method=self_review`。
- `status=validated`：真实独立审读的明确范围，记录实际审查者/方法；可选，不是交付前提，也不代表完全正确、实测或掌握。
- `verification=source_checked`：实际重新对照相关源码/资料/事件，并记录检查范围和出处。
- `verification=runtime_checked`：存在真实运行证据，仅证明记录中列出的机制；其他未运行部分仍明确保留。
- `needs_revalidation`：依赖的源码发生变化，需要重新检查。

不要求每篇都让你点批准。导师应主动核对重要事实，但自检存在局限，不能把自己的旧讲解或旧笔记当唯一证明。个人复述必须来自你，设计动机无直接依据就标推断，实验未做就写未运行。旧版本笔记没有 verification 字段时保守按未核对处理，不删除历史。

## 实验与开发模式

实验通常由你先预测，再尝试修改/运行，最后解释观察。Agent 可在已有授权范围内协助，但不会把学习调用视为运行生产操作或付费 API 的许可。

环境缺失时可继续静态追踪或设计离线实验；未运行不会标 Verified。必要实验 blocked 时，相关阶段保留未完成。

如果明确说“现在不是学习，请直接完成这个开发任务”，Agent 保存学习检查点并尊重开发目标。以后回到学习，会结合实际改动重新检查源码证据。

## Mermaid 图表与语法错误

模型必须严格使用对应图型的官方语法。默认把 ASCII ID 与中文/源码标签分开，特殊标签使用引号和官方实体转义，检查关键字、箭头、块与围栏闭合；未知渲染版本时避免新图型、新 shape 和复杂 HTML/Markdown 标签。图下还应说明节点和箭头的含义，不能让初学者只看类名箭头猜系统行为。

输出前逐项自检，有现成工具时对最终图实际解析/渲染；记录工具、版本、范围与未测项。解析通过不等于你的编辑器/平台一定渲染成功。可以说“这张 Mermaid 有 syntax error，请按官方语法修复”，模型应先修原图并重新检查；缺少原图或渲染器信息时只澄清必要信息，不让你自己改语法。

没有现成检查工具也不能虚称测试通过，不会仅为画图安装项目依赖或上传私人笔记。具体格式和可复用示例见 [图表协议](../deep-codebase-learning/references/diagrams.md)。

## 学习记忆由你管理

`.codelearn/` 在目标项目内，不在 Skill 安装目录。它保存结构化知识与个人理解，不保存完整聊天。

是否加入 Git、忽略、加密备份或仅本地保留由你决定。里面可能包含内部路径、你的回答和错误理解，不要随意公开。这个发布仓库的 `.gitignore` 只管理本仓库的本地开发材料，不会修改被学习项目的忽略规则。

同一个学习目录同时使用一个写入会话。不同项目可各自学习；多人共享项目不应混用同一份个人 mastery/state。v1不实现多人账户或并发合并。

## 更新 Skill

用 CLI 安装时优先只更新本 Skill，避免顺带更新其他全局技能：

```bash
npx skills update deep-codebase-learning -g
```

项目级安装用 `npx skills update deep-codebase-learning -p`。范围和安装目录以 [当前安装器文档](https://github.com/vercel-labs/skills) 与提示为准。手动安装时先更新克隆的仓库，核对版本与 [CHANGELOG](../CHANGELOG.md)，再替换**实际加载的安装目录中的 Skill 文件**，不要删目标项目的 `.codelearn/`。

更新前可备份安装目录；不要在包含用户定制内容的文件夹上盲目覆盖。学习记忆的 schema_version 和 Skill version 分开：新 Skill 遇到未知 schema 只读报告，不自动重置或迁移历史。

已经打开且读过旧版 Skill 的固定学习会话，更新磁盘文件后可说：“重新读取 $deep-codebase-learning 的最新 SKILL.md 和相关协议，保留当前进度继续学习。”不必换会话，也不必重建 `.codelearn/`；仅更新文件不能保证会话立即刷新已加载的旧指令。

## 常见问题

**没有自动启动？** 新会话中显式调用 Skill，检查安装了正确的整个文件夹，并确认打开的是目标项目。

**开局被问陌生题？** 应暂停题目，先交付全景教材、再渐进源码，不算答错。你可说“先从整体写详细教材，不要考我”；也可明确要求整课聊天。笔记是完整教学，独立验证在愿意且前置就绪时进行，不是阅读门票。

**阶段为什么未完成？** 让 Agent 说明当前 exit criteria 的缺项。必要实验、关键误解、个人复述或文章质量门禁未通过都会保留未完成。

**换分支后旧笔记还能用吗？** 先检查相关源码；仅受影响的记录标 needs_revalidation，通用语言知识不会因切分支全部清零。

**文件写入失败？** 不要把未保存进度当成功。Agent 应给出简短恢复记录；恢复写权限后先补齐再跨 Topic。
