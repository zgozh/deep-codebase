## 教学内容、交付和能力

Project Coverage 跟踪实际区域与机制覆盖深度，Knowledge Mastery 跟踪真实学习者能力，Reconstruction Ability 跟踪脱离源码可重建的系统。文件数、教材篇数和用户说“懂了”不能替代任何能力证据。

v1.11.4 默认正式交付是详细独立教材。聊天简短给范围与链接、随时充分答疑；明确整课聊天请求才展全文。所有渠道共用 [详细内容合同](../deep-codebase-learning/references/teaching.md#唯一教学交付合同)，局部答疑按问题范围，不能要求源码/官方资料/聊天补齐当前必要解释。

初学者默认：只提过名称、贴过源码或概述职责不算机制已解释。新概念在首次影响理解处给全称/白话/当前用途/例子，源码和解释紧邻，按具体业务场景及真实调用顺序展开。小课限制因果目标广度，不限制必要解释深度，不设字数目标；当前语言/框架前置先于依赖代码，范围大则拆连续中文小课。

路线仍从问题→能力→架构→代表端到端功能→源码机制开始；垂直业务触发重要配置/对象/异常等，横向审计补未进入主链的重要结构，最后独立重建。依项目生成完整路线，不机械套固定栈。每阶段定义 exit criteria，内容教材可交付而能力仍 waiting，不能用“文章完成”批准 Stage/Project 完成。

## 用户验收基线

原目标是在 AI 的长期引导下，从零理解真实项目全栈，能解释、修改、定位问题，并最终独立重建核心系统。后续 Skill 改进、公开示例和真实教材都对照下面十项职责，从实际正文说明哪里做到、哪里缺失；这是用户目标的持久基线，不是勾选表或新增教学流程。详细写法仍由链接中的唯一合同维护，教材作者不必加载整份设计文档。

1. **交付初心**：默认给可独立阅读的详细笔记，聊天简短链接、随时充分答疑；零基础读者不用自己找陌生词、翻源码或查链接补课堂。见 [交付与答疑](../deep-codebase-learning/references/notes.md#正式交付与聊天答疑)。
2. **业务与因果编排**：从真实问题、使用现场和架构分工开始，按初始化与用户动作进入调用、状态及结果；必要定义在首次依赖处教，不能照目录/定义顺序把入口留最后。见 [课程编排](../deep-codebase-learning/references/teaching.md#课程编排完整路线一个因果目标) 与 [路线生成](../deep-codebase-learning/references/planning.md#路线生成)。
3. **概念先教清**：当前新概念、字段、关键语法和表达式由问题、准确含义、机制与具体例子讲透；名称、全称或一句定义不算已教。见 [初学者默认](../deep-codebase-learning/references/teaching.md#初学者默认与导师责任)。
4. **完整源码与前中后**：当前完整内聚职责及必要上下游决定规模，长源码连续完整分块，不强贴无关整文件。源码前教问题/输入/准备，中间保真并明确教学注释，代码后正文逐行或小语义组充分推导参数、返回、函数/API 职责、调用位置、值变化和消费者；注释、标题、作者自评或后章不能补齐。见 [第五章合同](../deep-codebase-learning/references/teaching.md#第五章源码之前源码之中源码之后)。
5. **框架、底层与工程判断**：教框架何时通过哪个项目接入口参与，当前必要底层机制怎样支持行为；从真实约束推导实现、可行替代、开发修改和架构边界影响，不停在 API 近义释义，也不要求逐个读框架内核。见 [执行机制与数据](../deep-codebase-learning/references/teaching.md#执行机制与数据要讲到哪里)。
6. **官方资料进入正文**：实际读适用版本章节，把规则、机制、本项目语句映射和限制教进正文，再附直接链接；链接可开不等于断言成立。见 [官方资料教学](../deep-codebase-learning/references/teaching.md#官方资料如何进入教学)。
7. **失败与实际用法**：同一具体输入贯穿局部与全链正常/重要失败，解释停止点、残留副作用及消费者结果；真实使用、准备、操作、接入和修改影响须能按正文理解。见 [十章职责](../deep-codebase-learning/references/teaching.md#唯一教学交付合同)。
8. **十章深度与可读性**：每章承担自己的全部适用职责，每个行为单元具可定位职责小节；连贯段落、紧邻源码和实值推导让读者读懂，标题齐、篇幅长或单一全链正确不证明全篇充分。见 [十章合同](../deep-codebase-learning/references/teaching.md#唯一教学交付合同) 与 [笔记质量](../deep-codebase-learning/references/notes.md#note-quality-gate)。
9. **长期路线、记忆与能力**：保存偏好、实际教材范围、问题和返回点；逐步覆盖全栈及横向结构，最终独立重建。教材写出/读过不提高 mastery，能力等级只用真实学习者证据，文章完成不等于项目完成。见 [规划与横向审计](../deep-codebase-learning/references/planning.md)、[记忆协议](../deep-codebase-learning/references/memory.md) 和 [能力与重建验收](../deep-codebase-learning/references/evaluation.md)。
10. **返修保留与内容审读**：保留可恢复基线、正确源码与必要解释；重组受影响单元，去实质重复说明去向，不缩成摘要。自查或委派后的真实独立审读必须以正文为依据覆盖所有职责；源码/知识事实正确与教得充分分别判断，经验不能补漏。见 [写作与审读](../deep-codebase-learning/references/write-lesson.md#整节流程与保存顺序) 与 [返修保留](../deep-codebase-learning/references/authoring.md#返修保留教学内容)。

复杂或反复未达标时，在第一完整行为单元提前校准写法；整篇初稿实际通读，返修复读受影响范围，广泛重写才再全文读，不强制每篇多轮通读。发现未教的新 API、关键语法、框架机制或设计判断就指出对应正文缺口并修该处，不以小示例或历史“通过”代替本次接受。

用户尚未确认现有公开示例满足所需深度，真实欢迎页教材本轮返修仍为 self_review、用户未确认；这些范围不能记为本次用户验收通过。公开示例只经历有限静态审查，是小型完整功能读码示例，不是大型全栈代表课或普适高质量保证。历史确实执行的 V0、源码和知识事实核对仍保留各自证据，不据此宣称教学充分、用户认可、模型长期稳定或真实学习效果。

## 两种编写方式

默认单会话；首次提供一次主会话规划审查、子 agent 编写选择，未答继续默认，有选择则存当前合同与 journal 跨阶段恢复。这是 Skill runtime 的可选编写方式，与开发该 Skill 时的 Global 开发分工分开；无需子 agent 也可学习，不固定运行模型/档位、不增运行工具，宿主和用户限制优先。

委派是编写责任拆分，不是让子 agent 自己规划或写共享进度：主会话给有界目标/前置/真实源范围与唯一稿路径，子 agent 实读源码和官方资料写稿，主会话在独立上下文逐段核对并要求返修。仅主会话写索引/state/journal/mastery/coverage；不得并行编辑同稿。真实 author/reviewer 和检查范围进入 review，不能从子 agent 自报通过推断合格。失败时明确交还稿件所有权并可单会话接手，恢复无需旧子会话继续存在。见 [编写协议](../deep-codebase-learning/references/authoring.md)。

## 单轮工作流与正式教材门禁

v1.11.4 将十章内部的小节及展开方法放在现有教材模板，从初学者读懂具体过程逐步推导开发和架构判断；teaching 保留章职责，不再复制一份长清单。小节标题可语境化，内容可有依据合并/回指但当前必需解释仍落实，不以模板限制内容或制造填空仪式。同一次通读核每章实际小节的所有适用职责；每章原有一条记录带已核小节范围和具体落点/缺口，不新增每小节多维记录，范围文字不能证明实际审查完成。

恢复偏好与实际教材边界 → 选问题/主链，读真实源码和必要官方资料，在既有 brief 绑定实际小节任务 → 源块及对应逐语义正文连续充分写成，非源码小节落实具体例子和因果机制，尽早形成完整稿 → 一次实际通读、补正文缺口 → 必要 V0/保存与真实学习变化 → 简短主题/范围/链接。不先贴齐全部代码或填全章概述占位后再补深，不增逐单元移交门禁。single 自查可交付，delegated 主会话独立读子稿。讨论/中断仍及时 checkpoint，未变已读资料和检查证据复用。

官方资料要讲具体规则、机制、源码映射、能证明与不能证明什么，再直链和版本边界。源码事实、规则、静态推断、真实观察、假设例子与未知明确区分；私人源码/记录不上传外部服务。必要解释缺失先补，不把 unknown 当合格借口；实际未运行可明确静态范围。

[教学合同](../deep-codebase-learning/references/teaching.md#唯一教学交付合同) 规定详细语法/机制/场景/Why、真实源段与正常/失败值链；[作者流程](../deep-codebase-learning/references/authoring.md) 唯一维护写读返修。移除强制独审门票、分门报表、教材双 hash 与固定元数据布局。single 完整稿通读补缺后可 ready/self_review 并 delivered，validated 用于实际独立审读范围。简记方法/范围、重要出处和缺口处理，自己懂或能重放值链不替代必要解释。

返修先有一份可恢复旧版，局部修并对照正确必要教学单元保留，迁移目的已写好/入口有效/本节必需含义仍在。源码 revision 与 dirty 相关文件指纹用于可靠来源核对，不作为教材质量证明；仅广泛重写、源码范围大变或影响不明才全文重读。历史 validated 不批量洗白，教材完整不替代阶段/项目能力证据。

v1.9.0 建立十章次序，但规范中的“详细”“机制”仍容许浅层概述，旧成品没有充分示范架构、源码定位、逐行排版和框架推导。此前 Principal 静态审读并不等于用户认可；最新反馈明确拒绝旧例的深度和排版。v1.10.0 据此保留十章认知主干，重写展开方法与成品参照，而非再加质量清单或扩张学习流程。

架构章教实际角色、归属、生命周期与约定，流程凭真实调用贯通可见结果。第五章按初始化/用户动作的因果次序，每个行为单元采用八个固定职责小节，标题可语境化：问题/思路、触发输入、阅读准备、完整注释源码、逐行正文、局部运行/失败、机制判断、用法/上下游/接入/修改影响。源码前中后各承担不同任务，不重复同一用途，不把错误处理和发送等不同问题混为一个单元。当前职责的完整性决定源码规模，短示例不限制真实课；长源码连续分块保留必要行和上下文。第六章深化实际机制，不替第五章教当前单元。必要概念、具体正常/失败例和工程取舍不能缩成概要。

同一次语义通读按求值与行为边界逐块对照源码及紧邻正文，覆盖每章及每个行为单元；只凭正文还原读法、具体值执行和相关机制判断，同时核事实。现有 review 每章及实际每个5.x各一条短普通列表，分别记事实/教学结果与具体正文落点或表达式缺口，不用一条整课通过吞掉未核单元。任一必要未核或未补整课仍 draft，少数难点或全链正确不能放行。补缺重组受影响单元、保留正确源码和必要解释，局部修只复读影响链，不新增大矩阵、JSON 或工具。本地链接同时核语义。示例审读与历史证据边界见 [验证记录](validation.md)，静态结构检查不证明模型效果。PERSIST 继续维护正文/修订/版本/事件/指针，brief 携本轮 Skill 版本及最新反馈影响，冻结/终审核最终稿已吸收；中途变化只重开受影响内容。schema v1 不变。

本次修订纠正共享合同的尺度：小 helper 配齐十章仍无法示范系统功能，核源中找得到断言也不等于读者能复演全程。第二章用真实嵌套边界和载体讲架构协作，第四章区分启动/装配与运行并追全值链，第八章给完整操作教程，第六章展开实际最难的创建/分派/消费机制。一次正文独立复演同时核事实，审读者靠自身经验补出的步骤按缺漏修正文；不加报表、矩阵、工具或字数门槛。v1.10.0 的有限静态事实/可读性证据保留，但其完整教学质量参照结论撤回；这是共享示例和验收方法的缺陷，不能仅归责作者。

## Schema v1 的职责

| 文件/目录 | 主要职责 |
|---|---|
| state.json | 恢复入口、当前 Stage/Topic、返回点/待答、next_action、提交指针 |
| roadmap.md / stages | 动态路线、必要前置、真实交付范围、偏好/编写模式及能力合同 |
| project-map.md | 系统边界、业务入口、模块依赖和运行拓扑，不代替教材 |
| coverage | Inventory、discovered/seen/explained/traced/understood/verified 及对应实际证据 |
| mastery | L0–L6 的真实学习者表现、误解、复习与有效性；模型交付不升级 |
| journal | 结构化认知增量、备课/交付/能力范围、写入恢复信息，不是 transcript |
| knowledge | 当前必要知识桥梁、解释深度/来源与返回点，不造全仓词典 |
| notes/索引.md | 按阶段分组的中文教材入口、稳定 ID、范围/事件、质量/核对与接续 |
| notes/Stage ID-中文内容 | 每节中文详细教材、阶段综合；按实际内容分类，不堆统一主题目录 |
| notes/会话、项目总览、重建复盘 | 会话实际范围与最终系统综合/独立设计比较 |
| reviews | 测验/实验/文章与阶段门禁、审计、重建、恢复的实际证据 |

state 字段与 schema_version=1 保持，编写模式/是否询问存合同和 journal，无必填 JSON 扩展。模板空值不是能力证据。概念规范见 [concept.json](../deep-codebase-learning/assets/templates/concept.json)。机器路径相对项目根，Markdown 相对所在文档；写入限当前 `.codelearn/`，先核实路径和软链接边界。

中文阶段内容路径可按触及范围迁移旧主题/英文结构；保留稳定 ID、旧→新映射和历史能力，所有关联索引/Stage/state/journal/review/knowledge/roadmap/互链一起更新。冲突或占用不覆盖/强删，不为恢复全量迁移历史。

## 解释深度与学习者证据

investigated 是调查，prepared 是草稿/拟发解释，delivered 是完整教材实际通读补缺、必要 V0/保存/索引成功；single 可 ready/self_review，未完整稿仍 prepared；explained 指实际充分解释的教材段落/可见聊天及深度；learner-evidence 是实际用户回答/预测/实验/实现。文件 pending/committed 只是写入，不是教学或能力状态；正式交付不证明用户读过。

写出/阅读文章和导师讲解不会增加任何 mastery level，包括 L1。Coverage 的 explained 可以由源码支持的合格教材解释支撑，understood/verified 仍需用户表现与运行证据。提示程度与独立性分开，用户自述读懂不等于独立理解。教材可 validated，而阶段所需实验/restatement 仍 waiting；不存在伪造用户回答才能交付的要求。

个人问题、原理解、纠正和 Aha 只写真实历史，不能把 AI 的设计/润色当独立用户方案。笔记质量 draft/ready/validated 与事实核对 unverified/source_checked/runtime_checked/needs_revalidation 独立记录，既有笔记缺 verification 保守使用，当前修订补字段，不批量清零。

## 文件提交与中断恢复

POST-TURN：CLASSIFY → EXTRACT → EVALUATE → PERSIST → CHECKPOINT → STAGE CHECK → PLAN。pending 事件与 state 指针后更新必要内容/索引，校验才 committed，最后更新 state 指针并清 pending。它不是 Git commit 或数据库事务。

用稳定 event/条目 ID 补未完成写入，不能重复能力证据；冲突保留报告，不覆盖用户后来改动。共享状态唯一主写者，草稿作者仅拥有指定文件，无并发事务能力。无法保存如实报告并保留恢复记录，停止依赖成功保存的跨 Topic 推进，独立答疑可继续。

## 上下文、源码变化与边界

恢复只读 state、当前合同/路线、笔记索引/相关前课段落、近期 3–5 个事件及相关能力/知识/coverage/review。大文档搜 ID/标题读相关段；每节顺因果链加载必要源码，证据不足再扩大，不全量读历史/仓库，也不能以省 context 猜测。

Git branch/HEAD、dirty/untracked 与相关文件 hash 影响有效性，非 Git 用实际指纹。仅受影响链路/笔记/门禁 needs_revalidation，能力历史与通用知识保留；关键契约变化重开相关 Stage/项目验收。

产品只有 Skill + `.codelearn/`，无后台/服务/MCP/复杂 CLI。根目录 [校验脚本](../scripts/validate.py) 只供发布维护，不参与教学。真实模型遵守、长期效果和所有项目成功都须额外实践证据，不能从规范或结构检查保证。
