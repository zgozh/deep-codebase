## 本地结构检查

Python 3.10+用于维护者检查，不是Skill运行依赖：

```bash
python -m pip install -r requirements-dev.txt
python scripts/validate.py
```

检查name/description/version/许可证、UI调用元数据、JSON与YAML、初始状态/概念模板字段、Markdown本地文件/锚点链接、UTF-8、占位残留与发布路径范围。脚本只读发布文件；输出PASS不代表模型教学行为已验证。

CI使用相同命令。安装发现还可检查：

```bash
npx skills add . --list
```

这只列出Skill，不写目标Agent安装目录。真正安装与跨Agent行为应分别验证，不能从CLI发现成功推断兼容性。

### v1.11.5 开发试写方法与状态

本版先落实共享作者任务、冷读任务与按需 [单元校准](../deep-codebase-learning/references/teaching-calibration.md)，再用 [三个完整虚构案例](evals/cases.md) 作有限迁移试写。评测仅在维护开发时使用，不是 Skill 每课流程、运行依赖或适用栈白名单，不读取私人学习记录。源码单元示范与十章整课分别判断。

后续执行时，将选定案例的完整内容直接交给作者任务，或提供该案例的独立隔离副本，并附公共 Skill 与唯一稿件输出位置；不依赖作者只读合并文档的某段行号，不提供维护者答案、其他候选稿或先前结论。不新增抽取工具或多套公共fixture副本。作者按用户请求写完整十章；审读者先从冻结正文还原具体值与交接，再核源码/官方规则，事实与教学分别判断，沿用现有 review，不新增逐行表。退修保留首稿与实际缺口，不把有指导返修说成首稿盲测通过。
