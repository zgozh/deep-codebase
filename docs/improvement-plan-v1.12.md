## 1. 证据：退步是可以量化的

用同一口径复算四份真实稿件（CJK 字符 `U+3400–4DBF`、`U+4E00–9FFF`，排除代码围栏与标题行）。复算结果与验收报告的 33,534 / 16,079 / 48,721 / 23,556 完全一致，说明口径没有争议：

| 稿件 | 正文汉字 | 代码行 | 字/代码行 | 代码块数 | 平均块行数 | 块密度中位数 | ≥25 行且 <8 字/行的块 |
|---|---|---|---|---|---|---|---|
| 旧有效稿 S00-T03 | 33,534 | 772 | **43.4** | 55 | **14.0** | 29.6 | **0** |
| 新自然稿 A | 16,079 | 695 | **23.1** | 26 | **26.7** | 6.7 | **5** |
| 辅助稿 3,654 行 | 48,721 | 1,173 | 41.5 | 85 | 13.8 | 14.9 | 5 |
| Cobra 自然稿 | 23,556 | 414 | 56.9 | 16 | 25.9 | 16.6 | 2 |

三个判别量，直接对应三种失败：

1. **平均块行数 14.0 → 26.7**：旧稿每 14 行代码就停下解释一次，新稿把两倍的代码堆在一起再总述。这是「长源码块 + 短概述」的机械成因。
2. **每代码行解释量 43.4 → 23.1**：正文只剩一半，与验收报告的数字吻合。
3. **长块低解释块 0 → 5**：新稿出现 78 行配 520 字、93 行配 362 字这类段落；旧稿一块都没有。

同时要看清指标边界：**Cobra 的密度 56.9 高于旧稿，仍然判 FAIL**，因为它的失败是事实错误（`project.Copyright` 的输入来源说反）和个别段落收束不足，不是「薄」。所以：

> 机器指标只负责拦住「薄」和「堆代码」，不能替代语义审读。两者是并列的两道门，不能互相顶替。

## 2. 根因

### R1 门禁测错了对象

`assemble_note.py` 的 `--min-lines` 数的是**整份 Markdown 的物理行**。A 稿 2,231 行里有 797 行代码及围栏、687 行空行、137 行标题，这些全部计入 2,000 行门槛。结果是「行数达标、正文腰斩」也能通过。这是上一轮已经确认的结论，本计划把它作为第一优先修复项。

### R2 三阶段流程制造了「攒量 → 救量」

`draft → expand → finalize` 的设计意图是「先足量底稿，再专用增强」。实际执行变成了：

- 底稿阶段按行数目标堆到 2,389 行；
- expand 阶段理应对每个 5.x 单元判缺口，但真实轨迹里作者读了 `expand-lesson.md`，**没有读它指向的「当前源码单元落稿任务」**，增强没有真正发生；
- 最后靠主会话辅助返修补到 3,654 行，才勉强「内容合格」。

也就是说：流程名义上有三道门，实际只有最后一道人在看。模型不会因为文件更多就写得更深。

### R3 生成形状被规则放坏了

旧模板的要求是「长源码连续分块，每块紧邻充分正文」。新模板为了反对机械切分，写了「不按固定行数分组」「不设源码行数/字数下限」，模型读成了「大块代码是合理的」，于是块从 14 行涨到 26.7 行。

规则没有说错，但它只说了「不要机械切」，没有说「块大到一定程度必须切」。缺的是**正向形状**，不是又一条禁令。

### R4 同一个数字有五种口径

「300/600 字」在 `SKILL.md`、`teaching.md`、`notes.md`、`review.md`、`stage-note.md` 里各出现一次，分别被描述成「实质起稿预算」「只作欠展开诊断」「不逐段机械卡数」「规划与诊断」。模型接收到的是「这条可以不遵守」，于是真的不遵守。

同类问题还有整课下限：一处说「2000/3000 硬约束」，另一处说「不设整课总字数目标」。规则互相削弱时，模型选最省事的那条。

### R5 入口间接导致关键指令被漏读

`SKILL.md` → `expand-lesson.md` → `#当前源码单元落稿任务`，三级跳。真实轨迹证明作者只跳了一级。**任何需要「再点一次链接才看到」的生成指令，都等于没有写。**

### R6 写入方式本身在制造失败

A 稿 11 次、C 稿 13 次 `Script failed`，其中大部分是 `apply_patch` 匹配失败和 shell 引号问题（C 稿 7 次 web 调用引号错误）。这些不是教学内容问题，是「用 patch 传大段中文」的载体问题。它直接消耗时间和额度，也解释了为什么返修批次多。

## 3. 目标与非目标

### 目标

- **G1 内容**：同教学范围的正文有效量 ≥ 旧有效稿（Ragent S00-T03 的 33,534 汉字），且长源码块不再「堆完再总述」。
- **G2 自动性**：普通「带我深度学习这个项目 / 继续学习」一句话，单会话即可完成足量交付，不靠主会话辅助返修。
- **G3 流程**：一次主写 + 一次回读 + 至多两批集中修复；无同根因反复救稿；工具失败 ≤3 次。
- **G4 可恢复**：新会话「继续学习」能接续，保存顺序正确（笔记先于事件与状态）。

### 非目标

- 不重写教学合同的知识内容（十章职责、七位置、官方规则讲入正文这些是对的，保留）。
- 不新增运行时工具、服务、数据库、后台进程。
- 不追求「每小节精确字数」的评分仪式。
- 不要求一次生成零事实错误；要求的是错误能被自己的回读抓住，且集中修一次。
- 不在本轮证明跨项目、跨模型、长期学习效果。

## 4. 设计

### 4.1 生成形状：先定形状，再谈门禁

这是本轮唯一真正的杠杆。规则改成可执行的正向形状：

1. **单元内连续交替**：当前连续源码段（5–15 个有意义行）→ 该段解释（300 字起，复杂组 600 字起）→ 下一段。禁止「先贴完整方法，再统一总结」。
2. **单元 = 一个 5.x 行为单元**，不是一章。写完一个单元立刻保存该 part，再写下一个。不先写整本底稿。
3. **超过 15 行的职责必须切成连续小块**，每块紧跟解释；不因为「同一个方法」就整块贴出。切分点是真实动作/求值边界，不是固定行数。
4. **每单元一次完整写入**：用宿主的一次写文件操作落整个 part，不用大段 patch 拼接中文正文。

第 3 条是新增的、也是从数据里直接得出的：旧稿 14 行/块，新稿 26.7 行/块，差距就在这一条。

### 4.2 门禁：测正文，不测行数

改造 `scripts/assemble_note.py`，保留现有字节级安全写入（临时文件 + 硬链接 + 不覆盖目标），把数量门禁换成三项正文门槛：

| 门 | 含义 | 默认阈值 | 作用 |
|---|---|---|---|
| G1 | 全文正文汉字数 | 15,000（整课；可用 `--min-prose-cjk` 按本课范围覆盖） | 拦住整体腰斩 |
| G2 | 正文汉字 / 代码行 | ≥ 30（代码行 ≥150 时启用） | 拦住「代码多、解释少」 |
| G3 | 每个 ≥25 行的代码块，其后续解释 ≥ 8 字/行且 ≥200 字 | 硬失败 | 拦住「长块 + 短概述」 |

写作目标是每块 ≤15 个有意义行；25 行是硬失败线，中间留出容差，避免把正常的完整表达式判死。

计数口径固定写在脚本 docstring 里：排除代码围栏与标题行，只统计 `U+3400–4DBF`、`U+4E00–9FFF`；非中文笔记改用等义词数，不混算。

注意区分两个数字：G1 的 15,000 是**发布底线**（低于它不允许交付），不是质量目标；本轮验收目标是第 5 节 V2 的「≥30,000，目标 33,534」。底线低是为了不误杀范围更小的真实课程，目标高是因为这次要证明不低于旧稿。

输出必须可行动，而不只是一个错误码：

```json
{"saved": false, "error": "below_content_gate",
 "prose_cjk": 16079, "density": 23.1,
 "thin_blocks": [{"heading": "原行88–165：...", "code_lines": 78, "prose_cjk": 520, "need": 624}]}
```

`thin_blocks` 直接告诉模型「改哪一块、还差多少」，避免它回头重读整篇。

同时新增 `--check` 模式：只对单个 part 计算指标并打印，不写文件。写作循环变成：

```text
写单元 → python assemble_note.py --check 该单元part → 有 thin_blocks 就当场改这一块 → 下一单元
```

这样反馈发生在 1 个单元的成本内，而不是整篇写完之后。

### 4.3 流程：一次写透，有限修复

新的单次交付流程（替换 draft / expand / finalize 三段）：

1. 恢复状态，确定本节要讲的功能范围与单元清单（可含 6–10 个 5.x 单元）。
2. 逐单元写：源码段 → 解释 → 下一段；写完保存该 part；`--check` 通过再下一个。
3. 非源码章按章写，同样一次写完一章。
4. 整稿回读一次：对照源码核事实、核每块是否真的逐行讲、核跨章衔接。
5. 把发现的缺口**合成一批**修所属单元；修后只复读影响范围。
6. 装配 candidate（门禁全过）→ 原字节保存正式笔记 → 更新 review/索引/事件 → 最后写 state 指针。

硬性边界：

- 同一单元同一根因修两次仍不过，停止救稿，记 FAIL，保留 draft，不发布。
- 不因措辞、更多替代方案、可选深挖重开整篇。
- 不逐段计数、不按差几十字微补；门禁只在单元结束和整稿装配时跑。

## 5. 验证

### V0 门禁校准（不跑模型，先做，1 小时内）

用第 1 节的四份历史稿回放新门禁，预期：

| 稿件 | G1 | G2 | G3 | 预期结论 |
|---|---|---|---|---|
| 旧有效稿 | PASS | PASS | PASS | **必须通过**，否则阈值设错 |
| 新自然稿 A | PASS(16,079) | FAIL(23.1) | FAIL(5 块) | **必须失败**，否则门禁无效 |
| 辅助稿 3,654 行 | PASS | PASS | FAIL(5 块) | 失败，与其已有「粗组」审读结论一致，不算误报 |
| Cobra 自然稿 | PASS | PASS | FAIL(2 块) | 失败；其事实错误由语义审读负责，指标不越界 |

这一步是「门禁的门禁」：如果旧稿被误杀，或 A 稿被放过，阈值就必须重调，**不允许带着未校准的阈值进入行为测试**。

### V3 恢复与成本

- 记录墙钟、顶层调用数、失败事件数；与 A/C 的 11/13 次失败对比。

### 停止条件

- V0 不通过：只改阈值或指标，不进行为测试。
- V2 第一轮失败：定位到一条根因，改一次，重测一轮。
- 第二轮仍失败：停止，不再救稿；保留 v1.11.31 安装，发布「未通过」记录，并评估退回 v1.11.3 写作流程 + 新门禁的最小组合。

改动越大，越要先问「这样改会坏什么」。

| 改动 | 可能的新问题 | 拦截 |

| 用正文汉字数做门禁 | 模型改灌水、换词复述、堆排比凑字 | 语义审读仍保留；G2/G3 约束「每行代码的解释量」而非总量；明确禁止重复与空话，审读时按「是否教了新东西」判 |

| 删除三阶段流程 | 模型写两章就停、或跳过非源码章 | 单元清单在开写前确定并写入 state 的 next_action；整稿装配门槛要求十章齐全；`--check` 逐单元反馈 |

- 不再无限重试。V2 两轮不过即停止，把结论写清楚：哪一项没达到、卡在哪条规则、下一轮该换哪个假设。

## 11. 结构审计（v1.12.1）

正文门禁只量数量，答不了三个具体问题：名词概念讲没讲、代码块前中后是否展开、块后是否逐行。为此新增只读的 `scripts/audit_lesson.py`，检查四件事：

| 检查 | 判据 |
|---|---|
| 七位置 | 每个 5.x 必须有实际问题、架构位置、源码定位、4–5 连续源码、运行与失败、机制判断、用法接入七个 H4；代码必须出现在 4–5 区域 |
| 代码块前三节 | 「架构位置」≥200 汉字、「源码定位」≥150 汉字；低于 120/100 为硬失败 |
| 代码块后 | 每块解释 ≥max(200, 8 字/行)，段落数 ≥max(2, 行数/15)；`mermaid`/`text` 除外 |
| 概念四要素 | 第三章每个概念 ≥250 汉字，且包含定义、例子、项目映射、边界/代价之一 |

术语首现只给 warning，不进硬失败；审计不判事实对错，也不替代语义审读。它按规范标题解析，自由标题的旧稿不适用。

### 对行为测试稿的初测

| 项 | 结果 |
|---|---|
| 概念 | 3.1 691、3.2 403、3.3 291、3.4 520、3.5 653；四要素齐全（3.3 偏薄） |
| 代码块前 | 8/9 单元的「架构位置」只有 51–104 字，「源码定位」45–116 字，低于目标 |
| 代码块后 | 密度 66.3、长块薄解释 0；但 5.5 的 13 行块 176 字、5 行块 148 字、5.7 的 14 行块 181 字，低于 200 |
| 结论 | 概念达标；块后基本达标；**块前系统性不足**，是模板允许「一句话交代」造成的 |

据此把「前三个位置每节 ≥200 字、两个短段以上」写进写作入口与模板，并把结构审计纳入回读步骤；同时对该稿做一次 18 个前节 + 3 个块解释的集中补写。

补写结果：每个单元两节 201–277 字，3 处块后解释 252–289 字；`problems` 0，`warnings` 从 13 降到 11（全部 ≥ 目标值的 85%）。3.3 概念从 291 扩到 823 字并补了路径参数/查询参数、push 与 replace 的历史差异、「地址是状态的投影」边界；术语「代理」首现补了白话定义。终稿 44,973 汉字 / 密度 72.0 / 0 薄块 / 0 断链。
