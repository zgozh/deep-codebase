# v1.16 方案：源码之后，别再复述代码

日期：2026-10-30 · 基线 1.15.0

## 0. 问题

用户的判断：代码块后「绝大多数字眼都是代码块里的代码，真实内容占比少」。
先核实两件事：

1. **「一小段代码 + 一整块讲解」是设计吗？** 是。5–15 行一块、块后讲、再下一块，是为了让读者眼前始终有被讲的那几行。
2. **块后讲解变成了「每行贴一句、再翻译一句」是设计吗？** 不是。合同从没要求一段一行，写作者却把它执行成了逐行成段。

## 1. 证据：三份成品

统计对象是第五章每个源码块之后的正文（不含代码、标题）。脚本与原始数据在本机 `reports/v116/`。

| 指标 | 旗舰 Java 课 | Python 课 | v1.15 新生成课 |
|---|---|---|---|
| 代码后正文汉字 | 12,239 | 8,962 | 22,577 |
| 段落数 | 137 | 89 | 341 |
| **每段平均汉字** | 89 | 100 | **66** |
| **行内引用占字符比** | 45.0% | 51.0% | **46.1%** |
| **以代码开头的段落** | 66% | 57% | **66.7%** |
| 整行回贴（≥40 字符引用） | 130 | 79 | **201** |
| 最高单块引用占比 | 71% | 66% | **72%** |

一份 25 行的块（`onComplete`）被写成 **17 段**，平均 55 字，整行回贴 10 次。
按块看：v1.15 新生成课的 39 个块里，38 个引用占比 >35%、38 个段落均值 <100 字、38 个过半段落以代码开头、10 个块找不到一条框架/底层/语言事实。

**结论**：知识不是没有，而是被放在「复述这一行」之后当补充说明；读者读到的骨架是代码回声，框架契约、底层机制、设计判断退居段尾。这解释了「真实内容占比少」的观感——按字符算，近一半是源码。

## 2. 诊断：合同的三处措辞

1. `teaching.md` 原文：「逐行或按小语义组写多段充分正文」。句子本意是「每行都要覆盖」，写作者读成「每行一段」。
2. 六层检查放在**单元**末尾，且写明「不要求每块都写满」。于是知识被集中到「机制与工程判断」两节，块后正文只剩读法。
3. 门禁只量汉字：17 段各 55 字的复述，与 3 段各 300 字的讲解，在 G2/G3 眼里完全一样。

## 3. 设计：三段式（每块 2–4 段）

| 段 | 写什么 | 篇幅 |
|---|---|---|
| 值链 | 按执行顺序讲这一段；每行都覆盖，但用行号区间 + 连续读法，不逐行回贴 | ≤1/3 |
| 机制 | 至少一条「看代码看不出来」的事实：框架契约（谁在何时做、默认值、版本）、底层机制（线程/序列化/协议/索引/事务/渲染）、或语言规则（求值顺序/精度/可见性/浅拷贝）。断言被调方法的行为就贴决定它的实现 | 1–2 段，≥1/3 |
| 判断 | 为什么这样写、换种写法的代价、删掉或写错后用户看到什么、从哪排查 | 1 段，≥1/4 |

三条硬规则：

- **引用预算**：每段最多一处行内引用，整行只在首段引一次，其余用行号；引用 ≤24 字符。
- **遮住测试**：遮掉所有反引号内容，剩下的句子仍须通顺、能独立成立；读不通就是复述。
- **不逐行成段**：`}`、纯 getter、单行赋值并进值链段；语义组多就先切块。

六层随之从「单元级建议」下沉为「块级最低线」：每块至少一条 L1–L4 的事实，单元仍答五问（L3–L6 各一条）。

## 4. 不做什么

- **不加硬门禁**：composition 只发 warning，`problems` 与退出码不变，旧稿不会被判死。
- **不提高字数下限**：30/200/250/300/600 与 8 字/行全部不动。三段式是重排，不是加量。
- **不新增 H4、不改七位置**：三段写在原 4–5 区域内，用内容而非小标题区分。
- **不删事实**：返修改写时，原块讲过的值、条件、消费者、机制逐条保留；删掉的只能是「整行回贴 + 同义翻译」。

## 5. 验收

1. 同一块按三段式重写（`onComplete`，25 行）：939→751 汉字、17→4 段、段均 55→188、引用 49.7%→0.8%、整行回贴 10→0；补一条原文没有的事实（落库与发帧之间无事务）。
2. 三份教材重跑审计：`problems` 仍为 0；各新增 4 条 composition 告警，指向具体块。
3. 装配门禁、单测、`validate.py` 全绿。
4. 反例检查：重写块的字数比原文少 20%，但逐条对照事实清单，没有一条教学事实丢失；少的是复述。

## 6. 局限

- composition 是启发式：引用占比、段落长度、开头字符都能量，**「这一段有没有教新东西」量不了**，仍要靠回读与遮住测试。
- 只验证了三份 Java/React/Python 教材；Golang/Rust 未验。
- 没有重写整课，只重写一块做示范；全课改写需要下一次真实生成才能证明稳定。
