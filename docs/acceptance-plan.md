# 维护者教学与长期学习验收方案

本方案用于维护者执行验收，不从 Skill 运行入口加载，不增加每课工具、依赖、审批或报告。方案落盘不等于行为验收已执行；当前结果见末节及 [验证记录](validation.md#已有行为证据)。

## 冻结对象与判定边界

- 当前基线：Skill **v1.11.27**；仓库 HEAD `e8178e7ac0295593d928477e0e061e6ed6d03a4c`。这是 Skill 基线，不自动成为目标项目或所有输入的来源版本。
- 本批固定 v1.11.27 完成整轮验收，期间不修改 Skill；先汇总整轮结果，再提出改进建议，避免边测边改造成归因不清。
- 主验模型为 **GPT-6-Luna / max**，默认 **single**；delegated 作为另测可选能力，不能替代 single 通过。实际模型不可用则记录 NOT_TESTED，不静默换模型。
- 每批开跑前冻结：真实项目名称、源码 commit/branch、相关 dirty/untracked 内容、许可与使用授权；原始全部输入及换行；Skill 实际加载路径/版本；模型/推理档位、宿主、权限、工具可用性；用户普通提示、前置学习记录及实际范围。
- 源文件保留原生内容和身份；输入指南等教学材料单独标明来源，不能把某个 README 的来源说明外推给全部文件。公开材料可用不可变链接，私有材料只在授权本地保存。
- 教学唯一来源为 [十章合同及源码合同](../deep-codebase-learning/references/teaching.md)、[作者流程](../deep-codebase-learning/references/authoring.md)、[教材模板](../deep-codebase-learning/assets/templates/stage-note.md)；记忆与能力分别依 [memory](../deep-codebase-learning/references/memory.md)、[evaluation](../deep-codebase-learning/references/evaluation.md)，不在本页复制所有数值。
- 新完整普通课遵守 [SKILL 整课下限](../deep-codebase-learning/SKILL.md#整课交付硬约束) 及重要小节展开基线；局部问答和单元校准例外不能缩小整课承诺。整体篇幅不能代替第五章内部小节，充分旧文的局部补丁也不为新下限推翻重写。
- `notes.md`“无整课总字数指标”与 SKILL 的物理行下限需按适用范围查歧义，当前以 SKILL 明示优先级执行；这不是已证明的失败根因，不在验收中擅改合同。

结果只用 **PASS / FAIL / NOT_TESTED / N/A（具体理由）**。事实与教学两轴分别判定，关键失败不被平均分抵消；未经测试不能写 PASS。可以早 FAIL，完整 PASS 必须所有适用必测实际覆盖、全文逐章累计真正读完。真实初学者反馈不能被模型冷读替代；结论限定样本、模型与环境，不保证人人、所有项目或 100% 成功。

## 执行次序与继续规则

| 阶段 | 实际动作与产物 | 判定与后续执行 |
|---|---|---|
| A 审查者校准 | 按下一节匿名冷读失败/充分单元，留一份短证据 | 已有 FAIL 保留；后续由 Principal 独立检查弥补未校准代理判定，不取消独立测试 |
| B 一个真实完整课 | 冻结项目和普通提示，single 首稿；按全稿方法审读 | 分别判整课事实、教学、保存交付；无论结果均继续其他独立项 |
| C 另一项目与补充课 | 第二个不同真实项目/技术栈、不同控制流，再补一完整课 | 新完整课总计三篇、覆盖至少两个真实项目；分别判定，不要求 B 先 PASS |
| D 长期功能与恢复 | 在隔离 `.codelearn/` 状态 fixture 运行场景表；使用已核片段或明示 seeded 材料 | 不依赖 B/C 必须 PASS；逐项保留真实执行与准确状态证据 |
| E 稳定性与真人反馈 | 最难课同条件独立重复一次；收真实初学者反馈 | 独立重复按计划执行；真人反馈只按真实样本给结论，无反馈记 NOT_TESTED |

本批继续完成方案中所有可执行项，不因某项 FAIL 取消其他独立测试，也不要求用户重复确认。只有真实权限限制、指定模型不可用、所需人类输入缺失等实际阻碍才将受阻项记 NOT_TESTED，并继续其他独立项。冻结首稿及自评，不逐节反复返修；新完整课为三篇跨至少两个项目，加一次同条件独立重复，共最多四课。反馈修好的结果须记 **assisted**，不能改称原首稿成功；本批不以返修替代独立试写。A 的正式匿名校准及后续源码先行有界诊断仍 FAIL，B–E 在恢复执行前均为 NOT_TESTED。

执行完机器可执行项不等于全部 PASS，也不等于真人反馈已完成。缺少真实初学者反馈时保留 NOT_TESTED，不伪造反馈、不承诺人人学习效果；完成整轮可执行项后再统一总结结果和改进建议。

## A：先校准审查者

1. 维护者准备匿名材料：一个真实失败单元（含可独立核对的事实错及用途摘要式“逐句讲解”）、一个已独立核过的充分单元。不得为测试改写冻结失败稿。
2. 充分样本只取现有主例已核的 **§5.3 有界单元**；不把主例整篇认定 gold，不将它的尺寸当真实课程上限。选材维护者先确认样本与源文件对应，独立判断依据另封存。
3. 在一个新审查上下文先只给 raw inputs/sources、必要规则及读者前置，不给教材路径、作者结论、自评、预期缺陷、好坏标签或已知错误答案。先从源码冻结本次演算的完整关键输入、中间对象、分支和输出，以及展示源段必须教清的语句教学点；严格限本次因果目标，不额外精算无关细节，未核保留未知。小型原始输入保留完整关键状态，大对象只取本次必要范围，不打印全仓。
4. Principal 独立核对这段冻结结果；有错先校正或记 FAIL，不能带错继续。纠偏后继续须保留原错并标 assisted，不能称首稿自动成功。随后在同一上下文给匿名随机排序的教材，逐项将冻结事实与必要教学点对照真实正文位置；再仅凭正文判断初学者能否恢复语法/求值、绑定、状态、消费者及机制，缺失解释不能靠审查者经验补全。
5. 冻结首次完整审查输出，由维护者对照封存依据，记录实际表达式、正文位置、遗漏/误报与理由。最终目标恰好存在不能抵消中间值错误，其他次要缺陷不能替代已知核心缺陷；允许充分短语义组，不做每行×八矩阵、不重复读无关源码。此源码先行顺序仅作维护者一次冷读校准；当前有界诊断仍 FAIL，不是 Skill 运行时已修复的证据或每课新增流程。
6. 校准通过也仅证明此次有界区分能力。误放关键事实错、伪逐句讲解或误判充分单元时保留 FAIL，不将该代理判定当成已校准结论；完整课和其他独立场景照常执行，由 Principal 独立核对事实与正文，整轮结束后再总结审查方法的改进建议。

## B/C：每篇全稿怎样审

审查冻结首稿及原生 `.codelearn/`/review，不先看作者自评。Principal 独立检查，不能直接采信未校准代理的 PASS/FAIL。新稿、整体重写、无可靠旧基线或最终整体验收做一次完整冷读；分段读可累计，但记录实际范围、补齐截断，未读不能推成已读。已有局部修订仅复读受影响范围，继承仍有效的证据。

先从原始全部输入和源码独立推正常/重要失败值，再对照正文；随后只凭正文检验初学者能否复演。以下逐章覆盖**所有实际适用小节**，不能只检查章名：

| 章 | 内部展开的必要判据 |
|---|---|
| 1 业务 | 谁在何环境做什么具体操作、输入与可见结果、原限制及需要功能的原因；业务词首次就地说明 |
| 2 架构 | 图与正文给真实运行边界、实际位置、创建/持有/归属/生命周期及协作原因；目录树不能冒充架构 |
| 3 概念 | 依赖前先白话、通行全称与中文含义，再以具体例子教语法、规则、机制和易混边界；不能以术语清单替代 |
| 4 全链 | 初始化与每次操作分清，真实装配/调用及值的逐跳交接，必要正常与失败因果链返回 UI/终端，范围边界真实 |
| 5 源码 | 每个真实 5.x 的八职责和每个有意义源行均审，按下述专项执行，不因其他章讲过而豁免 |
| 6 机制 | 实际读适用版本官方规则，解释底层因果、真实项目使用和源码映射、限制与证明边界；裸链接不算 |
| 7 回放 | 同组完整输入和成员一致，正常/重要失败逐步给状态、返回消费者、停止点、残留副作用与两端结果 |
| 8 使用设计 | 可照做的环境/操作/信号，具体接线、排障与修改影响；以同组条件比较可行替代及其代价 |
| 9 答疑 | 基于真实问题或明确标示的可能误读，答案有推导及例子；不伪造用户误解/回答，不强制答题才能继续 |
| 10 收束 | 因果模型、实际覆盖和证据、未解边界、下一真实问题与符号；写笔记不等于用户掌握 |

不适用项可 N/A，但须给真实理由；不许通过缩范围、删当前难点或把必要内容推给未来规避。

第五章专项：

- 对每个 5.x 核八职责：问题/思路，真实触发/输入，定位/阅读准备，完整源码，紧邻逐句正文，局部运行/失败，机制/工程判断，使用/上下游/接入。第 4–5 项可交替合并展示，其余职责仍可定位。
- 每块代码之后的**原行小组正文**必须让初学者恢复语法与求值、实参形参和接收者绑定、具体输入输出及消费者、状态/副作用/失败，并教当前必要 API、框架底层机制和工程架构判断。不是每行八问，也不是“调用 X 完成 Y”的用途摘要。
- 覆盖所有有意义源行，连续分块讲清作用域与衔接；注释不代替正文，综合回放或其他章不能补当前语句缺讲。复用前课须定位已充分解释内容，并讲本次应用与值差异。
- 逐行核实际源文、完整项目路径/符号/原行/来源身份；原语句、注释、空行与闭合忠实，教学注释明确标示；省略范围/理由真实，不能删难行。展示行号不能冒充原行。
- 核所有假设输入与中间对象、数组成员/顺序、完整状态一致；局部投影明示。分别标源码事实、官方规则、假设/静态演算、runtime 观察与未知，不从静态调用推已到达 UI。
- 行数丰富是必要不充分；篇幅足、路径全或某难点正确都不能放行其他单元。充分短语义组按实际职责判断，不能把窄例外泛化整课。

沿用 [review 模板](../deep-codebase-learning/assets/templates/review.md#教材通读与修订note-quality)：每章一条短证据、每个 source 单元一条短证据，包含实际小节/原行范围、正文段落与具体表达式、事实与教学各自结论、缺口/未核范围。例：`5.x / 表达式：事实 FAIL（源…）；教学 FAIL（正文…仅用途，缺绑定/消费者）；已读…，未读…`。这是一条核查证据，不能用它代替本章全部职责。不得另造评分程序、关键词判优或每行×八项矩阵。

## D：功能与长期场景

采用隔离短状态 fixture，不依赖 B/C 整课必须 PASS。可复用 B/C 中事实准确性已经独立核过的片段，或使用明示 seeded 的材料；不得因此将失败教材升格为整课通过。不要求每项都生成长整课，不修改 Ragent 真实学习记录。每行记录执行输入、实际回复/文件 delta、预期不变量、结果；合成学习者回答显式标示且不能进入真实能力记录。只读合同/桌面推演不算行为执行。

| 场景与最小动作 | 必须观察的结果 |
|---|---|
| 首次学习，随后继续一个当前问题 | 全景→端到端→源码的动态路线；首课不等全仓精读，也不以陌生问卷开场 |
| 加一条最新深度反馈并继续 | 恢复最新反馈、当前阶段及已真实教过范围；prepared 不算 delivered，名词提及不算已教 |
| 同会话继续；另开全新上下文只给 source + `.codelearn/` | 两者均恢复身份、当前/返回点、待评估项和下一动作，不依赖旧聊天或子作者上下文 |
| 隔离 fixture 含较长历史、当前阶段与索引，执行恢复 | 轨迹先读必要 state/current/recent/relevant，按需要扩读，不全读日志/源码；留实际读取量与原因，不设字节门槛、不生成大历史过程文件 |
| 重要 Topic 收束、会话边界、Stage 条件成立；再显式请求总结 | 自动 Topic/Session/Stage 总结及显式总结保存实际范围；exit 不足可草稿，不完成阶段 |
| 有价值问答/中断后，在 pending 或 committed 指针落后处恢复两次 | 每轮实际变化留事件；按事件 ID 幂等补未写 delta，无重复事件/证据；集中状态收尾与指针一致 |
| 写完/读过笔记，用户只说“懂了”；另给可核独立回答 | 前三者不升 mastery；独立表现按实际概念升，真实与 seeded 回答来源分开 |
| 暴露前置知识缺口，再提出无关深挖 | knowledge detour 教必要前置并回返回点；depth boundary 保留当前必要深度，旁支有真实接续 |
| 中文笔记新增/局部迁移/返修旧课 | 中文路径、稳定 ID、索引、Stage/state/journal/review 引用一致；保留当前学习位置、旧历史及有效能力 |
| 切 branch/HEAD、改相关 dirty 文件、加入相关 untracked 文件 | 识别真实差异，只失效受影响链路/证据并保留历史；无关通用能力及已证据不全清零 |
| 新增前端/存储/配置分区，触发横向审计 | 动态全栈 inventory；unknown/pending 与 absent 有依据，重要基础设施/前端不得遗漏，pending 不可最终通过 |
| 请求安全实验；缺运行授权/工具 | 保留用户改动，区分命令示例与已执行；无实测不造 runtime，不强装工具/MCP/DB或启动副作用服务 |
| 请求独立重建/项目完成 | 真学习者承担设计与核心实现，Mini Version 有必要正常/失败运行证据；AI笔记或合成回答不能通过 |
| 默认未选模式；明确选 delegated；模拟作者中断 | 默认 single 不阻塞；委派仅在支持且选定时执行，作者文件独占、Principal 唯一共享状态写者，交还后接手 |
| 完整课交付，再普通提问 | 聊天短链接交付教材；直接答疑仍充分开放，实质缺漏修正文及受影响记录，不每问重写整课 |

恢复相关失败只重跑该故障点及影响链；项目最终完成必须另核横向审计与真实能力门禁，不能由 fixture 通过代替。

## 跨项目试写、图表与效率

- B 试写一个完整真实课，C 继续不同真实项目技术栈/控制流及补充课，例如异步 UI/API 与配置 CLI/存储，不以 B 通过为前提；新完整课总三篇、覆盖至少两项目，E 再将最难课按相同条件独立试写一次，共最多四课。保留全部首稿，不以逐节反复返修替代此轮独立测试。项目、commit、许可未冻结则尚未准备，不宣称已执行。
- 现有四文件 Python fixture 不是完整可运行项目，只能用于校准/局部证据，不能当跨项目完成。Ragent 是 Java + React，不能记成 Vue。
- 每次用普通 Skill 触发，不外加字数、目录、正确答案或额外展开提示；保留完整原提示和首稿。中性状态询问也留轨迹；任何内容纠错后的结果记 assisted。
- Mermaid 使用通用保守语法；有现成工具才实际 parse/render，分别记工具版本与结果。无可用工具只称自检、未渲染；不保证所有平台，不上传私源码，不强行安装依赖。
- 从原生轨迹记首次实质写入、完整首稿、重复无关读取、补丁/传输失败、晚期返工、实际完成范围与活跃区间。网络/容量等待单记，重叠或并行区间不重复相加；不把墙钟全归流程。
- 不用时间上限逼内容缩水。旧文先保存可靠基线，定点改并比较章节、例子、源码和必要解释保留；hash 只表版本，不证明教学完整。局部修订不重复全稿冷读，最终完整验收须累计覆盖全文。
