# 写入传输与局部恢复

有可直接调用的宿主原生编辑/patch 工具就直接用，遵从其真实 schema，不另起等待 stdin 的临时交互写稿进程；若经 `functions.exec` 调用 `tools.apply_patch`，统一采用下面的普通引号字符串数组加 `join("\n")`，不用 `String.raw`、含 Markdown 正文的模板字符串或大段 Windows 启动参数。没有此工具就用宿主已有的可靠 UTF-8 编辑方式，不安装工具、写包装器或新增脚本；这不限制项目教学中正常的 shell 操作。Windows 中文显式 UTF-8，Python 检查用 `-X utf8`；成功后复用同一传输方式。

按一个或相邻几个完整教学单元成批写入，源码与充分正文同批，相关缺口一起补齐，不拆成逐行微写或积成整篇巨补丁。用刚读到的短唯一稳定锚点及必要上下文，不用整页旧段或漂移行号。同一文件只写一个 `*** Update File:` 头，多处 hunk 按当前文件顺序排列，重叠修改先合并，不能重复同文件头或让后块再次匹配已改旧文。不为未改章节生成空定位，每个 `@@` 后须有真实上下文或增删行，不能连续放空 `@@`。原生 apply_patch 格式不混用 git unified diff 头；经 JS 传输时，空格、`-`、`+` 行前缀都放在普通引号字符串内，不能写成引号外的一元转换。下例用同一文件的两个标题定位两处非重叠修改，`@@` 后须逐字使用当前文件完整实际标题行，保留 `#` 前缀，标题层级和空格也须一致，不能只填标题文字。它仅示传输形状，不是课程样例或每课运行探针；Markdown 反引号可直接放在普通引号字符串内。

~~~javascript
const patch = [
  "*** Begin Patch",
  "*** Update File: path/to/note.md",
  "@@ ## 第一个标题",
  " 保留的上下文",
  "-旧正文一",
  "+新正文中的 `名称`",
  "+```python",
  "+print(1)",
  "+```",
  "@@ ## 第二个标题",
  " 保留的另一处上下文",
  "-旧正文二",
  "+新正文二",
  "*** End Patch"
].join("\n");
text(await tools.apply_patch(patch));
~~~

按实际返回分三类恢复：

1. JS SyntaxError、NaN、invalid hunk 或 schema 错：修请求拼装及工具格式，不改教学内容、调行号或重读来源。明确未执行的格式错误不触发重新搜证或重审。
2. expected lines/context mismatch：只读失败局部，取当前短唯一锚点重建受影响 hunk，保留已成功变更；不用旧长段重试。反复失配但有唯一章节边界和可恢复基线时，可可靠替换当前本地单元并核边界，不整篇重写。输出截断只续读未读范围。
3. 权限、I/O、容量或宿主中断：依实际返回与必要局部回读确认保存边界，不假定所有失败都原子地未执行，不绕过授权，不谎称已保存。

首次失败后，用当前本就要改的一个内聚小段确认恢复，再继续完整单元，不另建试验文件、计数器或预检脚本。同一未解决的拼装错误再现就停用该失败方式，改宿主已有可靠编辑；无可靠方式则如实标明未保存与阻塞，独立答疑可继续，依赖保存的推进须等成功。停用失败传输不等于停止教学任务，不重启整课、不删缩正确教学，也不设返修轮数上限。

成功后仅核这批实际 diff 和必要回读；误写只恢复无关触碰，不整篇回滚。按实际落盘阶段汇报，执行成功及必要回读未确认前不称完成。完整课文档 V0 一次收尾，集中写必要 projections，局部变化复用未受影响的有效证据。必要源码与官方规则查证仍须完成，不能为省时删掉。
