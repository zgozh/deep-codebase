# 写一节教材：按单元写透

这是唯一的写作入口。一次「学习/继续」请求里完成本节交付，不分成 draft、expand、finalize 多段，也不先写整本再回头补。

内容合同（十章职责、七个写作位置、官方规则讲入正文）由 [教学合同](teaching.md#唯一教学交付合同) 与 [唯一模板](../assets/templates/stage-note.md) 定义；本页只管「怎样把一节真的写出来」。

## 写作形状

- 一节 = 十章；第五章由若干 5.x 行为单元组成，一个单元就是一次写作任务。
- 单元内按真实动作顺序推进：**当前连续源码段（5–15 个有意义行）→ 该段解释（300 字起，复杂组 600 字起）→ 下一段**。
- 超过 15 行的职责切成连续小块。切分点是真实动作与求值边界，不按固定行数，不拆断一个表达式、括号或 JSX 结构。
- 禁止先贴完整方法或整章代码再统一总结；禁止用职责概述、术语列表、裸代码代替解释。
- 每个单元一次完整写入一个 part；part 之间不要用大段补丁拼接中文正文。

字数预算是起稿要求，不是逐段计数游戏：每个语义组按 300/600 字写足，整节由下面的门禁检查，不靠空行、代码、标题或换行凑量。旧稿的有效解释要保留，不为字数重写。

预算要和单元数一起算：一个 5.x 单元（块前三节 + 块后三节 + 单元引言）通常 1.5k–2k 汉字，七单元加十章非源码内容约 22k–28k。用户给了总量上限时，**先减单元数，不把每节压到目标值以下**：装配门禁的 15k 下限只证明「不是概述」，不证明每节够厚；结构审计的 warnings 才是每节厚度的信号。

## 单元循环

1. **选单元**：一个真实符号或内聚职责，配一个具体行为问题、一份真实输入、一个可观察结果和一个真实消费者。
2. **写前三个位置（每节 ≥200 字，两个短段以上）**：实际问题与实现思路；架构位置、真实触发与具体输入；源码定位与阅读准备。这三节不能只写「父链 + 一句输入」：架构位置要给真实调用/装配表达式、谁在何时运行、样例实参与初始状态、值由谁持有、结果交给谁；阅读准备要给完整路径、符号、原行范围、版本，以及读懂本段所需的前置概念。写不到两段，说明还没把读者带进这段代码。
3. **写第 4–5 位置**：源码段 → 代码后原行小标题 → 充分正文 → 下一段。先教字面读法，再教语法与求值/绑定，再追具体值、时机、状态和消费者，最后讲必要机制。写完本单元后回头用 [六层五问](teaching.md#六层讲解每个单元要回答的五个问题) 检查：不用框架特性手写要做什么、最终落到哪个系统机制、为什么这样分层/传参、删掉会怎样、10 倍量级先坏在哪；答不上的层补进机制或边界段，不新增小节。
4. **写后三个位置**：同输入局部运行与重要失败；核心机制与工程判断；怎么用、上下游、接入与修改影响。
5. **自查该 part**：跑下面的 `--check`；`thin_blocks` 非空就改这些块，不重写整篇。
6. **保存该 part**，接下一个单元。

一个单元写完并自查过再进下一个；不要在同一个 part 里合写多个 5.x，也不要一章攒完再检查。

## 正文门禁

装配器量的是**教学正文**，不是物理行：统计代码围栏与标题行之外的汉字（`U+3400–4DBF`、`U+4E00–9FFF`），并按代码块分组检查解释量。

单 part 自查（写文件吗？不写）：

~~~text
python /path/to/skill/scripts/assemble_note.py --workspace /path/to/project/.codelearn --check --part 写作/课ID/05-01.md --source-root /path/to/project --final-note notes/阶段/正式课.md
~~~

整节装配 candidate 时同样默认开门禁：

~~~text
python /path/to/skill/scripts/assemble_note.py --workspace /path/to/project/.codelearn --part 写作/课ID/01.md 写作/课ID/05-01.md --source-root /path/to/project --final-note notes/阶段/正式课.md --output 写作/课ID/candidate.md
~~~

三项门槛：

| 门 | 含义 | 默认 |
|---|---|---|
| G1 | 正文汉字总量 | ≥ 15,000，整节装配时检查；单元自查不查，整节可显式覆盖 |
| G2 | 正文汉字 / 代码行 | ≥ 30（单元自查 ≥20 代码行时生效，整节 ≥150 行时生效） |
| G3 | 每个 ≥25 行的代码块，其后续解释 | ≥ 8 字/行且 ≥200 字 |

单 part 自查只查块质量（G2/G3），不会因为「一篇单元不足 15,000 字」而误判；整节总量在最终装配时检查。需要更严的单元目标时可显式传 `--min-prose-cjk`。

不通过时返回 `error: below_content_gate`，`gates` 说明哪几项没过，`thin_blocks` 直接列出要改的块：

```json
{"saved": false, "error": "below_content_gate", "gates": ["thin_source_blocks"],
 "prose_cjk": 4120, "density": 22.5,
 "thin_blocks": [{"line": 88, "heading": "原行88–165：...", "code_lines": 78,
                  "prose_cjk": 520, "need": 624}]}
```

按 `thin_blocks` 改这些块：补当前源码的逐行读法、具体值和消费者，不是加空话。改完重跑 `--check`，通过再继续。

门禁只挡「薄」和「堆代码」，不判事实对错，也不替语义审读。事实、机制、边界仍要在回读时对照真实源码核。

## 结构审计

正文门禁只量数量。结构审计补它看不到的五件事：每个 5.x 是否有七个位置、代码块前三个小节是否写够、每个代码块后是否有足够解释与段落、第三章每个概念是否有定义/例子/项目映射/边界、Mermaid 标签是否宽到会压线。

~~~text
python /path/to/skill/scripts/audit_lesson.py notes/阶段/正式课.md --json
~~~

结构审计只针对十章正式课：阶段总览、索引、复习卡不是这个形状，跑它会得到一堆「缺章」噪声，不要拿它去改总结。

`problems` 是硬失败，按 `unit` 找到对应小节补写；`warnings` 是低于目标值但未硬失败的项，回读时逐条判断要不要补。审计不判断事实对错，也不替代语义审读。

## 整节流程与保存顺序

1. 恢复状态，确定本节范围与单元清单（通常 6–10 个 5.x）。
2. 逐单元写 + `--check` 通过，保存 part。
3. 非源码章按章写，一次写完一章。
4. **整稿回读一次**：对照真实源码核事实；核每个代码块后是否真有逐行讲解；核跨章输入、概念、时序和结论衔接。回读时逐个断言核对：**正文说某个函数或方法做了什么，就必须在正文贴出决定这个结论的实现**；只给函数名、行号或用途叙述不算教过，补 include 或把断言缩小到已展示的范围。有 Mermaid 就按 [图表协议](diagrams.md) 实渲染并目检标签压线。然后跑结构审计（见下），把 `problems` 合成一批修完。
   **API 自检**：凡是出现框架 API 的段落，至少有一句「框架在背后做了什么、约定是什么」；只有「调用 X 完成 Y」的，补上 L3/L4。
   **闭卷自测**：合上源码，只读这一课，逐条回答——关键结果依赖哪一行同步代码／为什么没有出现某个看似必然的请求／对象到字节经过哪几步／本课链上最隐蔽的组合失败是什么／某个设计如果漏做会怎样／新增一个事件或字段要改哪几处、漏一处什么后果。答不上或只能靠猜，说明对应章节还没讲透，补写后重测。
5. 把发现的缺口**合成一批**修所属单元；修后只复读影响范围。
6. 用全部门禁装配 candidate。
7. 原字节保存正式笔记 → review/交付索引 → 学习事件 → 最后写 state 指针。

顺序不能反：先保存正文，再写交付事件和 state。中途保存 part 可以，但 `prepared` 不等于已交付；门禁没通过不写 delivered。

## 返修预算与停止条件

- 同一已读范围的全部缺口合成一批修，不逐个发现逐个开轮。
- 同一单元同一根因修两次仍不过：停止救稿，保留 draft，记录真实原因，本轮判失败，不发布。
- 不按「差几十字」逐轮补写；不因措辞、更多替代方案或可选深挖重开整篇。
- 事实错、必要源码缺失、关键语句没有解释，必须修；风格和额外深度不阻断交付。
- 修完只复读改动及其上下游，不重读整本。

## 非源码章与局部交付

- 非源码章按章一次写完整章，按 [教学合同](teaching.md#唯一教学交付合同) 的章内职责展开；不强行插入源码单元。
- 用户明确要求局部/单函数源码笔记时：仍是正式教材，保留模板、七个写作位置和 G2/G3，只免整节总量；装配时加 `--no-prose-floor`，其余门禁照常。
- 即时答疑、明确短总结按其交付写够当前问题，不扩成整节，也不套完整课门禁。

## 委派

用户选择子 agent 编写时，每个子作者只写分到的独占 part，不碰共享学习状态、其他 part 或项目代码；主会话负责规划、合并、整稿回读、门禁和保存。默认仍是单会话，不需要子 agent。

## 写入与工具

- 每个单元一次完整写入；坏 part 直接重写该 part，不在坏补丁上连续重试。
- 中文正文不放进 shell 命令参数；命令只传路径。
- 官方资料集中查一次，讲进正文，不逐个 API 触发一次查询。
- 具体写入、渲染和装配细节见 [写入约定](writing-io.md)。
