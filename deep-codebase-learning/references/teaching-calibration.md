## 共用的完整源码

明确虚构的 Python 3.11 同步快照注册器。完整示例路径是 `/fictional/snapshot-demo/main.py`，下列块第一行为原行1，含空行共21行；定位采用该路径、符号和块内原行，不声称磁盘存在该文件。无第三方库、事件循环或后台任务。三种写法都解释这一份代码，包含直接调用者和状态消费者。

```python
class Snapshot:
    def __init__(self, value):
        self.value = value
        self.listeners = []

    def subscribe(self, listener):
        self.listeners.append(listener)
        listener(self.value)
        return len(self.listeners)


state = {"last": None}


def render(value):
    state["last"] = value


snapshot = Snapshot("ready")
token = snapshot.subscribe(render)
print(token, state["last"])
```

## 写法一：职责概述

`Snapshot` 保存当前值和监听器。`subscribe` 注册监听器、通知当前值并返回数量。`render` 更新状态，调用方打印结果。

这是准确的导航摘要。初学者仍不知道 `render` 与 `render()` 的区别、`self` 从何而来、通知发生在赋给 `token` 之前还是之后，不能据此独立推演当前代码。

## 写法二：伪逐行——值链正确仍未教会语句

原行1–4定义快照对象的初始化方式。原行19用 `"ready"` 创建快照，起初 `value` 为 `"ready"`，`listeners` 为空列表。原行12准备 `state = {"last": None}`，原行15–16的 `render` 负责更新其中的最后一次值。接下来，原行20调用 `snapshot.subscribe(render)`，原行7先把 `render` 存入监听器列表，列表变成 `[render]`；原行8立即同步通知当前快照，因此 `state["last"]` 在本次订阅返回前就变为 `"ready"`，没有等待未来事件或后台任务。

原行9返回列表长度 `1`，原行20将它保存为 `token`。回调产生的状态变化与订阅返回的数量是两种结果，原行21同时读取它们，最终打印 `1 ready`。正常路径中，`render` 返回的 `None` 没有用于这个输出，`token` 也不是取消订阅的标识。若把通知删掉，`token` 仍为 `1`，但状态保持 `None`；可见只检查返回数量会漏掉首次通知是否发生。

失败路径也由同一顺序决定：若换成在原行8抛异常的回调，原行7已经把该回调加入列表，这个引用不会自动撤销；原行9的返回、原行20的本次赋值和原行21的打印均不会完成。将添加监听器移到通知之后，正常结果可以相同，失败时却不会留下该引用。因此修改顺序要比较已发生的副作用，不能只看成功输出。

这段正文的具体值、同步时机、两条结果路径和失败判断都正确，也有逐组原行定位，仍只是可信的流程概述。它没有教读者怎样读原行3两侧的 `value`：参数名与 `self.value` 为何不同，`self` 如何得到本次实例；没有解释原行20的属性访问如何得到绑定方法，裸写 `render` 如何作为函数对象绑定给 `listener`，为何不能直接换成 `render()`。原行8从属性取值再调用、原行16的方括号条目赋值与给名字重新赋值的区别、原行9先求 `len(...)` 再由 `return` 交回结果，也仍由读者靠经验补齐。能复述这条值链，不等于能从当前语句独立推演另一输入；已有失败演算也不能补掉这些读法。下面写法三在同一源码后展开这些缺口，供同一次语义审读对照，不另开核查轮次。

## 写法三：充分语义展开

### 问题、位置和读前准备

本单元要回答：订阅者怎样在 `subscribe` 返回前就得到已有快照？初学者不必先懂事件系统。这里的“回调”是把函数交给另一个函数，由对方决定何时调用；这个例子决定立即调用。赋值把名字关联到一个值；圆括号表示实际调用，裸写 `render` 则取出函数对象。字典用键找到值，列表按顺序保存对象引用，修改容器会被持有同一容器的代码看到。`None` 表示尚无结果，不是文字 `"None"`。

类是创建具有数据和方法的对象的定义；`snapshot` 是其中一个对象。方法是关联于类的函数，`self` 是此处接收调用的那个对象。`def` 执行时创建函数而不执行函数体；缩进划定函数体。因此阅读先理解原行1–9、15–16的定义，真正的业务动作在原行19–21。以上完整源块就是本单元源码；路径 `/fictional/snapshot-demo/main.py`，原行1–21，核心符号 `Snapshot.subscribe`，入口原行19，消费者原行21。

### 原行1–4：先创建保存快照的对象

原行1的类体创建 `__init__` 和 `subscribe` 两个方法。原行19的 `Snapshot("ready")` 创建实例并调用它的初始化方法：新对象绑定给 `self`，字符串 `"ready"` 绑定给 `value`。原行3中等号右侧的 `value` 是参数；左侧 `self.value` 是该对象的属性，二者不能混成一个名字。原行4的 `[]` 新建空列表并保存到同一实例的 `listeners` 属性。构造完成后，这个对象关联到 `snapshot`，其 `value` 为 `"ready"`，`listeners` 为 `[]`。另建实例会执行另一次 `[]`，本源码没有把列表放成所有实例共用的类属性。

### 原行12、15–16：准备一个真实的消费者

原行12先创建字典并把它关联到模块级名字 `state`，键 `"last"` 的初值是 `None`。原行15的定义把函数对象关联到 `render`；此时不修改字典。实际调用 `render("ready")` 时，其参数 `value` 才得到 `"ready"`。原行16修改既有字典的一个条目，没有给名字 `state` 重新赋值，因此不需要 `global state`。`render` 没有显式 `return`，调用正常结束返回 `None`；它的有用结果是字典变化，原行21会读取这一变化。

### 原行6–9、20：注册内部就发生调用

原行20先求右侧 `snapshot.subscribe(render)`，完成后才给 `token` 赋值。取 `snapshot.subscribe` 得到绑定方法，调用时 Python 自动把 `snapshot` 作为 `self`，唯一显式实参 `render` 绑定给 `listener`。若写成 `render()`，会先调用 `render` 且缺少参数，尚未进入 `subscribe` 就报错；本源码传递的是函数对象。

原行7的 `self.listeners.append(listener)` 把同一个 `render` 函数对象放到实例列表中，列表成为 `[render]`。`append` 的返回值没有消费者；变化留在列表里。原行8取出实例属性的值 `"ready"`，随后执行 `listener("ready")`，也就是 `render("ready")`，于是 `state["last"]` 变成 `"ready"`。这次函数调用同步完成后才继续原行9；注册并不自动意味着等待未来事件，本代码也没有遍历列表或发送后续更新的操作。

原行9的 `len(self.listeners)` 此刻为整数 `1`，`return` 把它交回原行20，后者才完成 `token = 1`。变量名 `token` 不证明它是可取消订阅的标识：这里只返回当前数量，没有取消接口。原行8得到的 `None` 被忽略，与原行9返回的 `1` 是两条不同返回路径。

### 原行21、失败与修改判断

原行21先读取 `token` 的 `1` 和字典的 `"ready"`，再由 `print` 按默认空格分隔、末尾换行输出 `1 ready`。这是静态演算，未运行。它同时观察返回值和回调副作用，说明结果不是只靠 `subscribe` 的返回值传递。

当前 `render` 在给定输入下没有主动抛错。若以后传入的回调在原行8抛出异常，本源码没有 `try` 捕获：原行9不执行，原行20不完成赋值，原行21也不会到达，而原行7已经添加的引用不会自动撤销。这个推断来自实际顺序，不是声称当前正常例子已报错。若把原行7移到8之后，立即回调仍会发生，但异常时列表不再留下该引用；若删去8，新订阅者将不能立即得到已有值，状态会保持 `None`。是否需要回滚或延迟通知取决于业务契约，不能为模仿异步系统擅改当前设计。本单元只解释注册与首次消费，不教授不存在的更新广播、线程安全或取消功能。

### 规则来源与证明边界

这里把 Python 的规则用在具体实参和状态上：[Python 3.11 函数定义](https://docs.python.org/3.11/reference/compound_stmts.html#function-definitions) 区分定义与执行；[实例方法](https://docs.python.org/3.11/tutorial/classes.html#method-objects) 解释绑定对象；[列表操作](https://docs.python.org/3.11/tutorial/datastructures.html#more-on-lists) 说明 `append`；[赋值](https://docs.python.org/3.11/reference/simple_stmts.html#assignment-statements) 与 [return](https://docs.python.org/3.11/reference/simple_stmts.html#the-return-statement) 区分绑定、容器修改与返回。链接对应维护时实际读取的3.11文档，网页当前标记3.11.17；它们支持语言规则，不证明虚构程序运行或学习效果。

## 连续源码与紧邻正文：先算通过滤，再解释输出

以下是另一个明确虚构的 Python 3.11 局部例子，路径 `/fictional/review-demo/main.py`，不是私人项目源码。契约是从记录中选出可见项目：保留原顺序，跳过标记为隐藏的项，空标题拒绝整次调用，正常返回去掉两端空白的标题列表。输入约定为含字符串 `title`、布尔值 `hidden` 的字典列表；不示范输入类型校验。这不是完整八职责单元或十章课，也未按当前扩写基线验收，不作为真实课尺寸上限；这里只对照同一实现的读法。

薄概述可以完全正确：“循环过滤隐藏项，清理标题，检查空值并返回列表。”但它没教 `continue` 跳过哪些动作、空值何时产生、异常与返回的差别。尤其不能把隐藏项的标题拿来当正常输出。开写先确定同组正常值：`[{"title": "旧项", "hidden": True}, {"title": " 新项 ", "hidden": False}]`；失败例只把第二项的 `title` 改成两个空格。下面在真实执行顺序中分别推演，不另造演算文件。

### 原行1–5：建立结果并排除隐藏记录

```python
def visible_titles(rows):
    titles = []
    for row in rows:
        if row["hidden"]:
            continue
```

`def` 定义接收 `rows` 的函数，函数体到调用时才执行。`titles = []` 每次调用创建一个新列表，用来存放这次返回的标题；输入列表与结果列表是两个容器。`for row in rows` 按输入顺序把每个字典依次绑定给名字 `row`，不是一次取出所有标题。方括号在 `row["hidden"]` 中表示按键读取当前字典的值；本例契约保证它是布尔值，`if` 在值为 `True` 时进入缩进分支。`continue` 结束的是当前这一次循环，执行会转去取下一条记录，既没有结束整个函数，也没有自动返回空列表。

代入正常输入，第一轮 `row` 是标题为 `"旧项"` 的隐藏记录，条件为 `True`，所以跳过后续清理、检查和加入结果的动作；此时 `titles` 仍为 `[]`。第二轮才轮到 `" 新项 "`，其 `hidden` 为 `False`，跳过 `continue` 而进入下一源块。这里先过滤再处理内容，是契约选择：隐藏项即使标题为空也不会导致当前函数报空标题错误。若把校验移到过滤前，就会连不准备展示的记录也校验，改变失败条件；不能把两个顺序称作完全等价。第一块末仍在函数和循环内部，下块沿原缩进继续，不能补造闭合或返回。

### 原行6–9：从当前可见记录产生标题或停止

```python
        title = row["title"].strip()
        if not title:
            raise ValueError("empty title")
        titles.append(title)
```

`row["title"]` 取的是当前第二条记录的字符串，不是所有记录的标题；点号取得该字符串的 `strip` 方法，圆括号立即调用它。本例没有参数，移除两端的空白并返回字符串，原字典中的值仍为 `" 新项 "`，返回的 `"新项"` 才绑定给局部名字 `title`。下一句的 `not` 对字符串的真假判断取反：空字符串为假，因此 `not ""` 为真；非空 `"新项"` 为真，因此本次条件为假。正常执行跳过抛错句，`titles.append(title)` 将 `"新项"` 加入结果列表，此时结果是 `["新项"]`，其中没有第一条隐藏记录的 `"旧项"`。

失败例中，第二条记录的两个空格经 `strip()` 得到 `""`，于是进入条件分支。`ValueError("empty title")` 创建表示值不符合要求的异常对象，`raise` 才把它抛出；函数在此停止向正常返回推进，后面的 `append` 不执行。若调用方没有捕获，异常继续交给调用方处理，不能把它写成函数返回了错误字符串。这解释了当前契约为什么拒绝整个调用，而不是静默跳过空标题。改为 `continue` 会使同一输入正常返回列表，却隐藏无效数据，两者对消费者有实质区别。当前函数没有修改输入字典，也没有外部写出；局部结果列表即使已有条目，也不会因抛错而自动交付给调用方。

### 原行10：把正常结果交给真实调用者

```python
    return titles
```

此行与 `for` 同级缩进，位于循环外：必须完成所有记录的循环后才执行一次。正常例在第二轮追加后已无下一项，`return titles` 结束函数，将列表对象 `["新项"]` 交给调用表达式的消费者。明确虚构的调用现场是 `names = visible_titles(rows)`，右侧函数正常返回后，左侧名字 `names` 才绑定到该列表；若随后 `print(names)`，看到的是 `['新项']`。打印是消费者动作，函数内部并没有打印，也没有把清理后的标题写回 `rows`。这条正常正例同时满足过滤与输出契约，不能用已被跳过的 `"旧项"` 展示功能成功。

失败例在原行8抛错，因而到不了此行，赋给 `names` 的这次赋值也不能完成。把 `return` 缩进到循环里则会提前结束，第一轮就可能返回，后续记录不再处理；它与现在的“遍历完再返回”不同。上面的分块保留连续原行及真实缩进，正文在每块后解释本次动作，无须在另一“逐行正文”小节再复制一遍。规则依据是 [Python 3.11 for](https://docs.python.org/3.11/reference/compound_stmts.html#the-for-statement)、[continue](https://docs.python.org/3.11/reference/simple_stmts.html#the-continue-statement)、[字符串 strip](https://docs.python.org/3.11/library/stdtypes.html#str.strip)、[真假判断](https://docs.python.org/3.11/library/stdtypes.html#truth-value-testing) 及前文的赋值、return、raise规则；这是静态示意，没有运行或学习效果证据。

## 非源码章节对照：边界为何这样划分

薄概述：“调用方提供数据，函数处理后返回，双方解耦。”它没有解释本次双方究竟承诺什么，也不能指导改动。

较充分的局部叙述：在上面的虚构功能里，调用方持有原始记录并决定何时展示，`visible_titles` 只负责从一次输入计算展示标题。双方交接的是内存中的列表和字典，没有网络请求或数据库。调用方承诺字段类型符合输入契约；函数承诺过滤隐藏项、保持可见项顺序并返回清理后的标题，遇到可见空标题则抛错。因此调用方要分别安排成功结果的展示与异常处理，而不能认为得到空列表就代表调用失败。空列表也可能是所有记录都隐藏时的合法结果。

结果另建列表而不改输入，使调用方仍能用原始含空白标题作编辑展示；这是具体的数据归属选择，不是“解耦”一词就能说明的收益。若为了省一个结果容器而原地删记录、改标题，其他持有同一输入的界面或缓存也会看到这些变化；调用方原来依赖保留原文的行为就受影响。是否值得改要看真实数据量及共享关系，不能从这个小例推断性能瓶颈。这里展示非源码章如何用场景、契约、具体值和替代后果展开判断；第一、二、三、六、八章仍须各教自己的适用任务，不能以第五章写充分代替，也不为每章复制相同推导。

## 怎样使用这个差异

第三种写法提供了从未教概念到表达式、值、时机、消费者和后果的推导，读者可据正文复演，而不是靠审读者自己的经验补全。前两种可以作摘要，不能承担本单元教学；尤其写法二说明，正确全链与具体值演算并不等于当前全部语句已教会。充分版本也只在这个单元范围内作示范；十章整课仍按原教学合同审读，不能把一个好单元推成全课通过。换语言或真实大项目时保留这种因果解释，源码规模与所需机制由当前职责决定，短示例不是尺寸或展开上限。

教学迁移提示：表达式产出与消费动作也需要分开讲，例如 Python 的 `SystemExit(0)` 构造异常对象，`raise SystemExit(0)` 才抛出该对象；未被捕获的该异常使解释器以0退出，单写构造表达式不等于退出。依据为 [Python 3.11 SystemExit](https://docs.python.org/3.11/library/exceptions.html#SystemExit) 和 [raise](https://docs.python.org/3.11/reference/simple_stmts.html#the-raise-statement)；其他调用仍要读直接实现，不能由此推成“构造器没有副作用”。这是一种跨语言读法提示，不把该语法或本页示例语言当作 Skill 适用边界。

## 可选迁移对照：解释与核源的区别
