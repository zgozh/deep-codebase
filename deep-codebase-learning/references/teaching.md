# 初学者教材的教学合同

## 初学者默认与导师责任

默认读者没有编程经验。项目业务、架构、语言语法、符号、框架、API（Application Programming Interface，应用程序编程接口）及当前行为所需的底层机制，凡此前没有充分解释，就按未知教。会启动项目、贴代码、用过名词或说“懂了”不能替代独立能力证据；只提名称、职责或链接不算已教。真实已有能力保留，仅减少对应重复。默认未知不是已证实缺口，导师漏讲不能记为用户答错。

导师主动识别前置，不让读者列陌生词。概念在**第一次需要它的句子之前或该句内**先给准确名称、中文白话和当前用途，包括第一、二章的业务与架构介绍。不能先写 Store、Hook、依赖注入等名词，再让第三章补救。所有本课新涉及名词、专业词和概念都须详细展开：准确全称和首次短释用于引入，随后从当前问题建立通俗模型，结合具体源码、值或使用例，讲清当前链路的接入口、必要机制、相近概念的区别与反例及设计含义。涉及表示、计量或状态时，先讲本次操作处理的是什么、按什么单位或状态规则变化，再用具体值推演；模型须让初学者说明当前对象/输入如何按规则得到输出、经历生命周期或走到失败，解释中出现必需的新概念先补，不能把通用词名算作已教。一个名称、全称或算对的结果本身不教会这个模型。按概念实际需要选解释载体，不给每词套固定问卷或写术语百科。模型有能力不代表初学者已有这些知识，精简规范与流程不能压缩教材。审读须从正文判断读者能否解释本次操作，不能靠审核者自补前置。第三章系统深化本课基础，第五章就地应用，第六章深入共用机制，分工避免重复；后续新知识仍须在依赖代码前补齐，第六章不能接收延期的必需前置。不用未解释的词解释另一个未知词。

最新教学反馈写入当前 stage/journal，跨课恢复。详细、逐行或带着讲官方资料意味着当前必要解释必须充分，不能用长输出或大量注释替代；先修真实缺口，不重启整套课程。

## 课程编排：完整路线、一个因果目标

路线由仓库实际业务和功能决定：项目问题 → 能力 → 架构分工 → 代表性功能或系统事件 → 渐进真实源码和机制（有前后端则贯通）→ 其他能力 → 横向审计 → 独立重建。首次先交付项目全景，不开陌生题，不把路线表当教材。全景已有充分正式教材则继续当前课，计划和草稿不算交付。

每课围绕一个因果目标，如“取消后哪一步停止、哪一步仍可能完成”。小课限制无关广度，不限制必要解释；范围大拆连续完整小课，保存起止符号与返回点。内部暂作接口边界的旁支也说明来源、输入、输出和当前影响，但不声称已教其实现。语言与框架前置太多时先写必要前置课，再回主链，不贴陌生代码等待未来解释。

## 唯一教学交付合同

正式笔记是可独立阅读的详细教材，不是聊天摘要、职责表、审查报告或源码索引。先按 [交付类型入口](../SKILL.md#开始或继续) 区分用户请求：长期课程每节含 S00 全景与单主题首课都适用整节正文门禁，作者自选窄主题或拆课不能豁免；用户明确局部/单函数专题时只免整节总量，仍适用本合同。正式笔记和显式完整聊天课堂采用下面的**十个顶层教学章节，保持顺序与适用职责**；这是每节认知骨架，不是十个业务步骤或项目固定阶段。真实流程步骤放第五章5.x因果单元，不改成十个流程章。标题可随场景自然措辞，不能任意合并成自由布局；确不适用的章给实际项目/内容依据，沿既有review短记说明。聊天局部答疑、阶段综合及用户明确短总结/简短笔记按其交付选择组织，不硬套正式源码课，也不冒充完整教材。

| 章 | 教什么、怎样展开 |
|---|---|
| 1 业务场景与本课目标 | 让读者认出真实需求：谁在什么环境下做什么，现有做法遇到什么限制，为何需要本功能。从具体起始输入讲到完整的期望可见结果；应用课说明实际入口、操作及可观察请求/响应，不能只有“读完会理解”。业务词使用处先说明。 |
| 2 系统位置与架构分工 | 让读者建立真实系统地图：用有嵌套边界的架构图区分实际运行环境、框架库、项目代码和外部参与者，箭头标明调用、数据、网络或状态等载体，给图例及逐段协作解释。讲创建者、持有者、生命周期、输入输出和状态归属，从实际约束解释为何如此划界及改变边界会影响谁。给完整项目路径、符号、原行、版本和可点击定位；不重复第五章代码。目录树不替代架构，架构图不冒充调用时序，不为凑层次虚构数据库或控制器。 |
| 3 读懂本课所需的概念 | 写成连贯的基础概念课，按当前功能的理解依赖安排小节，集中深入教必要语言/API及分派、所有权、生命周期、错误与状态等工程认识，不把解释散成各处随口释义。由准确名称和当前问题进入机制，结合带具体值的真实源码或明确标示的教学示意、实际操作、真实链路与框架映射、适用官方规则，推导具体例子、易混点和设计含义；按概念选择合适载体，不给每词套问卷或只作文字描述。缩写给通行英文全称和中文，不编项目名全称。第一、二章首次使用仍就地短释，本章集中深入，第五章讲当前代码中的实际应用，第六章深化系统机制；前文必需含义不能延期，必要语法和 API 在依赖代码前教清，不写术语百科。 |
| 4 端到端流程与本课边界 | 让读者沿同一功能复演全程：先讲必要环境、配置、入口和装配/注册，再从用户动作追真实调用者与被调用符号，逐跳给输入、URL、对象或状态变化、框架/网络/存储交接和最终可见结果。初始化与每次运行分清，用真实源码定位解释为何交接。多参与者功能默认另给时序或数据流图并逐段讲，编号箭头摘要不能替代。只排除真正无关内部，不把接入和返回链留到未来来省第五章深度。 |
| 5 真实源码逐段逐行精读 | 全课主体，按下文源码之前、之中、之后的不同任务展开因果源单元。完整职责源码、代码后充分逐行正文与局部回放不能退化为几行代码加两句用途。 |
| 6 关键机制与官方资料解读 | 解开本功能最难的一处实际机制：哪个接收者在什么时刻创建哪个对象，注册如何变成分派，框架怎样调用项目代码，输出由谁消费；需要时深入生命周期、同步/异步及并发。用真实语句和实际读过的适用版本官方规则推导步骤与限制，难抽象可配标为教学示意的手写小例。不重复第三章概念或第五章 API 用途，不用官方 URL 代替规则正文。 |
| 7 同一组数据的正常与失败回放 | 用前面同一输入拼完整正常过程，再改变实际重要失败所需条件；呈现各交接的具体值、条件、状态前后、返回或异常及消费者，讲停止点、残留副作用、两端可见结果与限制。静态推演不冒充实测。 |
| 8 设计取舍与使用/扩展方法 | 让读者会按本篇使用并知道怎么改：完整说明目录/环境/输入准备、启动、操作、期望输出和失败信号；前章接入概述在此展开为实际教程，不机械重复。再给具体改动、必须同步的调用/配置/注册/消费者及原因，对当前约束比较可行替代和代价。展示命令不等于执行；尊重用户跳过应用检查的选择。 |
| 9 易混淆点与带答案复习 | 针对本课表达式、机制或分支说明误读；问题紧跟充分答案和正文回指，供阅读自检，不要求先答才能继续。正式能力测验另按就绪规则。 |
| 10 本课收获、证据边界与下一课 | 总结实际能解释的因果关系，列未展开内部/未知/未运行边界与下一具体符号和问题；不把文章交付写成用户已掌握。 |

章节骨架防遗漏，标题齐全不等于讲透。章内小节及具体展开方式见 [教材模板](../assets/templates/stage-note.md)：默认依章内小节写，标题可语境化，合并/回指依模板入口的内容优先边界；每小节适用职责须逐一在正文落实，当前必需含义、机制与具体值不能省掉。用能导航的自然小标题、连贯短段落及紧邻例子展开，从初学者读懂过程走到开发与架构判断；不把模板当填空仪式或内容上限，不另造术语词典或备课矩阵。标识放行内代码，选择性加粗关键概念和结果，不加粗整段，不用链接墙或多列表替代推导。第七章要让读者实际跟完值链和失败后果，第八章须在当前约束下具体比较可行方案，第九章给完整解释而非一句答案，第十章说明真正得到的因果认识及证据边界。每章写适合当前内容的实际教学，不制造不存在的失败、状态或插件。确实不适用的部分给简短具体理由，例如纯静态常量没有异常传播；不能借此豁免相关值含义、消费者或错值后果。

### 全景、配置、脚本与测试如何适配

多参与者功能默认同时给第二章的真实架构图和第四章的时序/数据流图，遵守 [图表协议](diagrams.md)，图后解释节点、边界和载体如何对应正文。单个纯函数没有系统协作时可不画图，但微型 helper 只能校准局部语法和推导，不能作为完整项目功能教学达标的代表。

第一节全景仍按十章认知次序，明确写“本课建立系统地图，尚未逐行追完实现”。第五章用实际 README/清单/入口/配置的有据片段解释组成和相互支持的证据，不假装精读代表链全部方法；第六章只教已核实机制，第七章可给标明静态/假设的业务流程示范，未核实支路保留未知。业务/系统图和实际仓库依据是此课主体，不堆虚假精读和失败。全景适配不免整课下限或充分扩写；已展示的实际源码仍按真实语义分组充分教，不能只贴代码/用途概述，后续源码课再深入尚未覆盖实现。

配置课第五章换成完整相关配置与读取/绑定代码，追字段来源、优先级、生效时机、消费者和改错后果。脚本课追入口、工作目录、参数、控制流、输出/退出码及副作用；测试课追前置数据、动作、断言对象、为何能证明行为、模拟边界和漏测风险。简单字段、枚举、数据对象也以实际值追来源/合法含义/消费者和具体错误后果，避免字段字典；没有的机制不强造。

### 第五章：源码之前、源码之中、源码之后

优先按初始化与用户操作的因果次序展开完整源单元，以有具体输入、可观察结果/状态和真实消费者的本课内聚问题为边界，可是一整个方法、组件或内聚职责段，不因同在一个方法而纳入其他独立职责。先讲实际入口与装配，再顺真实调用进入实现；必要定义在首次依赖处解释，不能以“理解依赖”为由照原文件定义顺序讲、把入口留到最后。本课必要调用、输入、状态、当前失败及消费者涉及的真实源码仍须完整展示并逐句教清，不能删当前难行或伪称已教。跨出当前职责交代真实范围、接口影响和既有roadmap/coverage中的回收或接续；返修不能静默缩小已承诺范围。源单元规模不由示例的108行、八行方法或五行摘录决定，不强贴整文件或整仓，不设源码片段行数或源码字数下限。解释正文采用下述试行扩写基线。

新课选范围时，某依赖若只需接口，就说明真实接口、当前影响与后续回收，不为显充分大贴实现；但若当前对象、类型、初始状态、控制或返回结论依赖创建、注册、适配、默认值生产者、实际调用者或回调消费者，须沿决定该结论的真实交接找到最小完整职责实现，纳入本课源码与具体值链。只列路径、符号和角色用途不算展示实现，不能以“上游准备”或“框架自动”跳过必要生产者。无需展开不决定当前结论的整套框架内部。一旦展示真实实现，即使归为上游依赖或阅读准备，也须在源后充分解释全部有意义行，返修不得删已承诺的必要代码规避，必要上下游仍须保留。

每个有行为单元在自身5.x标题下保留下面八项教学职责，采用**七个可定位的写作位置**：第4项源码与第5项逐句正文必须放在同一“4–5 连续源码与紧邻逐行推导”区域交替展开，不能另设“完整代码”和“逐句推导”两块。八项职责由[唯一模板的七个H4位置](../assets/templates/stage-note.md#5x-真实符号本单元具体行为)承担，职责名固定且可附本课语境，不能重述成八项替代目录或散落单元外。5.x命名真实符号与本次行为，不是整课共享的5.1–5.8八职责；同一文件中回答不同因果问题的独立行为分别成单元，紧密合作的内聚职责可同单元展开，不机械要求一函数一单元。4–5区域重复“当前连续源码及准确教学注释/提示→代码后的真实原行小标题及充分正文→下一块衔接”，两项职责仍各可定位，其余六项各有自己的位置。不先贴完整方法大块、再到另一区域补解释；完整方法由必要连续切片累计保留，不因此缩代码。真正一个语义组可用一个源块，多个独立动作就交替展开，不设每块任意行数上限：

- 1. 实际问题与实现思路。
- 2. 架构位置、真实触发与具体输入。
- 3. 源码定位与阅读准备。
- 4–5. 连续源码与紧邻逐行推导：每个真实连续源块及明确教学注释之后，立即接原行范围小标题与每行/小语义组充分正文，再继续下一源块，累计保留完整职责。
- 6. 同输入局部运行与实际重要失败。
- 7. 机制与工程判断。
- 8. 怎么用、上下游、接入与修改影响。

#### 用户指定的完整课交付下限

唯一数量与足量交付合同已迁至主入口 [整课交付硬约束](../SKILL.md#整课交付硬约束)，包含完整课下限、正常排版、禁止凑量、局部/旧文边界及未完成状态；本锚点保留供原有调用定位，下述小节与语义组基线继续适用。

#### 试行扩写基线：重要小节要展开到什么程度

本节数字用于实际写作：行为组 300 字、复杂组 600 字是交付要求，不是可选的「起稿预算」。每块先按 5–15 个有意义行展示源码，再写足该块解释；块过大就继续切，切分点是真实动作与求值边界。审读以实际字面语法、具体值绑定、消费者和必要机制是否教清为准；缺这些仍阻断，不能用总量或“已充分”自评放行，也不能借预算之名删薄正确教材。代码、标题、链接、重复或换词复述不能抵解释量。需要定位明显欠展开时才粗看实际解释正文（中文按汉字、其他语言按相当段落量），不把Markdown和API标识符Length当正文。数字是本项目偏好的工程试行，不是官方建议、科学最优或质量保证；事实、完整源码、逐行推导及十章职责全部保留，充分旧文不为计数重写。

| 当前教学位置 | 默认有意义正文展开目标与任务 |
|---|---|
| 重要行为单元：实际问题与实现思路 | 200字以上，约2–3个实质段落。从具体限制推到可行解决思路，再落到当前目标为何需要这段实现。 |
| 架构位置、真实触发与输入准备 | 200字以上，约2–3个实质段落。给真实调用/装配表达式、谁在何时运行、样例实参和初始状态、值的持有者与结果消费者；列源码路径不算交接解释。 |
| 源码定位与阅读准备 | 准确路径、符号、原行范围、版本和本段必要前置，不凑最低字数。完整真实源码保留准确且明确标示的教学注释或紧邻阅读提示，源码体量不计正文。 |
| 代码后首次解释的有意义行为/机制语义组 | 每块 5–15 个有意义行；代码后按 300 字、复杂组 600 字写足，约 3–6 个或更多实质段落，由装配器按块检查。在合适行为边界解释实际语法、操作数绑定与求值，再追具体值、时机、状态和消费者，推到当前 API/框架/底层机制及设计原因。分组按真实动作与求值边界，不按固定行数，不给每行或每个 API 重建八小节问卷。 |
| 同输入局部运行与重要失败 | 300字以上，展示具体中间值、分支、停止点、残留状态和可见后果；正常与失败沿同一输入条件推演，不重复笼统警告。 |
| 核心机制与工程判断 | 500字以上，约3–5个实质段落。从当前限制与实际机制推导成立原因，比较至少一个当前具体可行替代，用同组正常值及重要失败条件说明行为差异，再解释条件改变时的取舍和影响；只重述流程、定义 API 或说“解耦”不够。 |
| 怎么用、上下游、接入与修改影响 | 300字以上，约2–3个实质段落。用一个具体改动追实际接线位置、数据/契约与结果消费，解释漏接会出现什么可观察行为，以及返回哪个符号/问题继续；文件检查清单本身不够。 |

复杂组按当前读者实际需要的新解释判断：首次遇到的框架介入/回调生命周期、多阶段异步与返回交接或跨对象状态变化，需要展开其时序与机制，不能仅凭方法短或作者熟悉归为简单组。表中语义组目标针对一个有意义的行为/机制范围，不针对每个纯括号或闭合行。

其他章节的重要解释小节默认250字以上、约2–3个实质段落，核心架构、概念、机制或设计决策小节500字以上。首次深入教的新核心概念按此500字级展开：从当前困难进入通行全称/中文白话，以具体用法和例值推到项目机制、相近概念边界与设计含义；必要非核心术语在首次影响理解处随句教清，不给每个符号强套500字。结尾导航、可核证据边界和单纯定位不凑字。每个实质段落都须独立教一个新的当前知识点，用实际表达式、值或条件及原因/例子支撑；不能把一句话断成三段，也不为琐碎行强造设计替代。

常规新稿按基线充分起稿，不能因方法短或审读者熟悉省掉实际表达式读法、具体值链、机制与必要边界。纯定位/import、重复闭合/声明可简写；共享机制可精确回指已充分正文，仍解释本次输入、变量与行为差异。审读发现欠讲时补当前源码后的缺失推理，不去别章凑量；已充分短段不因数字机械退稿，也不为计数扩写旧文。短小行为仍承担自身前中后职责，不能用父节总述或未来课豁免，所有有意义行仍要覆盖，不缩短完整承诺或免除整课下限。

按 [作者流程](authoring.md#源码写法输入) 逐单元写：每个 5.x 写完立即用 `--check` 过正文门禁并保存，再写下一单元；整节写齐后整稿回读、批量修缺口，最终装配过同一门禁才发布唯一 note。表中预算用于写足解释，全部适用小节详细展开、内容充足和字数多仍优先；不以少批保存压内容。扩写与收尾共用一次实际审读，同次核当前展开量、关键事实、必要解释及可读性，具体缺口定点补写并按影响范围复读，收尾核整节门禁、未核范围和衔接，不无限预读研究或复审。缺失教学补内容，可短写范围按上段处理；量够仍不能放行明显事实错、源码大段无解释或漏整章。正文优先，不增加证明文件、计数脚本或逐节反复计数。

一次厚写一个连贯目标/单元，用当前值例、机制原因和具体替代填真实缺口，不为展开量引入无关概念。目标确实太大时拆成连续且职责完整的课程，保留完整计划内容、每课起止与接续；不能静默删代码、用附录替代当前必要解释，或把未来课程当作已教。

纯声明、常量或实质重复结构可合理合并并教实际消费者；重要方法不因短而豁免。不同问题的行为方法分别成单元，不能把错误处理与发送等不同职责混成一个单元，令其中一个没有自己的问题和输入准备。三处分工是**之前建立问题与阅读准备，之中保留实现及就地提示，之后推导语句、运行和判断**；不是将同一事实复制三遍。全链前面介绍过也不豁免本单元，后章深化不替代此处展开。

#### 源码之前：带着具体问题进入实现

用“实际问题与实现思路”“架构位置、真实触发与输入准备”“完整真实源码与定位”等自然小节带读者进入：从具体限制推导为什么需要这段实现，打算怎样解决；它在本链什么位置；真实哪个表达式/装配点让谁在何时调用它。带入同一具体实参、初始状态，并指出调用者会怎样消费返回值或副作用。纯声明、常量和重复结构可合并讲解，但须说明实际消费位置与值的作用；方法短或业务简单不能成为省掉本单元教学任务的理由。

阅读准备交代必要的 import、字段、构造器、参数、闭包捕获和声明从哪里来，先补首次所需概念；不让读者猜自由变量。定位必须包含**完整项目相对路径、符号、原文件起止行、源码版本和可点击入口**，只有文件名或不可点击的行号不足以定位。**先确认项目自身的 repo 根**：项目目录若只是某个父仓库的子目录，不能把父仓库的分支与 commit 当成本项目源码版本；项目没有独立 repo 时写「本地快照，无 repo 元数据」，不借用外层仓库身份。公开仓库优先不可变提交 permalink；私人/本地源码用按文章层级正确计算的相对链接或宿主支持的完整本地文件链接，正文仍给原行范围和版本，不为造公开链接上传源码。**原行从实际 checkout 文件或保留原始换行的不可变版本 raw/blob 取得；网页、搜索及文本抽取器的显示行号不代表源码原行，不能直接引用。** 核对实际范围和该范围的内容逐行对应、链接目标确为本符号/语句；不能仅以行号在文件长度内验收。定位本身不是教学。

#### 源码之中：完整真实职责与教学注释

真实源码由已核本地raw按include范围渲染，原语句、原注释、缩进和空行不手抄/改写。教学注释或阅读提示置于生成围栏之外，明确标为补充，不改真实源码。首个完整单元同次回读七位置及全部源组，先核真实API签名、类型、输入输出、忽略返回与登记副作用及后续消费者；区分注册/解析/回调、生成器/模板/生成应用的阶段，同值不等于同一对象或一次读取。只读当前必要定义/适用官方规则，白话、具体值、机制与工程判断仍须写入正文。

实际读取该版本文件，按本课因果职责通过source include和渲染保留完整相关源码、原注释与空行，不以方法边界替代教学边界。生成默认沿真实执行/动作顺序：当前有意义动作的连续原行跨度（5–15 个有意义行）→该范围的充分字面/值链/消费者/机制解释→下一跨度，不先积压多个未解释源块再综述。完整函数由连续跨度累计保留，原子表达式或内聚分支可整块，不按固定行数或刻意拆断表达式/括号。块末仍在函数、循环或条件内部就承接原作用域，短说当前变量/状态和下一执行点，不补造闭合、返回或省掉难行。整个5.x仍一次连续写作任务，不逐跨度另开工具调用、part或审批；正确丰富旧文放回相关跨度旁保留，不压缩成用途摘要。教学提示在围栏外，不能代替正文。实际原行、真实上下文和前中后职责仍可定位，不强贴无关整文件；省略列真实范围及不影响本目标的理由。

原行范围存在仍须核内容逐行相符。JSX、条件、try 结构不能删去真实中段后补造 `/>`、花括号或返回值冒充原文；教学改写单独标示。行号属于源文件，不是展示块编号。源码演进先区分历史真实版本与编造，旧片段不能按新版本无标记引用。

#### 源码之后：逐行理解，再运行与判断

紧邻每个完整职责代码块或连续原行块，用“原行31–33：接住输入并建立两种状态”一类独立小标题，逐行或按小语义组写多段充分正文。不能停在一句中文翻译，指还要继续值链和机制推导，不是省掉基础逐句白话读法；**所有有意义行都须在代码后有对应正文，不能只挑关键行**。分组依据当前表达式、独立规则、分支及求值/行为边界，不按任意行数。当前有意义的方法签名、类型声明与参数不能略过；import、闭包及关闭结构按实际作用交代，许可证、空行、重复纯闭合可合并。声明式语言、模板、配置和样式也就近讲规则的字面含义、对象与效果，不能并成用途综述。相邻重复可回指已充分教学，但本次值、绑定与消费者仍当场说明。完整职责可累计连续小块，每块后立即充分解释并保留上下文/原范围，不先堆多块再总结；不用逐行宽表、电报式要点或每符号问卷。

每组按实际输出顺序展开：基础逐句白话读法→字面语法、类型与绑定→同值演算→机制与工程判断。先把眼前语句怎样读说清，解释关键字/符号、复合类型、变量来源、函数值及参数对应关系，不用另一个未释术语代替；再代入具体值，追求值/调用时点、实参与形参、状态、返回消费者及失败停止点。由这些行为推导语言/API/框架和必要底层原因、当前设计及可行替代，不从工程意图反推源码结果；涉及框架接管仍讲真实入口/触发者。原预算不是上限，分层不是各写一句或每行重建栏目；跨行共同机制可充分讲后映射回当前语句，避免百科重复，局部回放/机制小节仍承担综合推演。

“原行150–177：接收三种元数据”后只说“保存元数据供后续使用”，即使原码完整、标题带原行、注释准确，也没有解释各次调用的实参如何求值和绑定、各自读取或修改什么、结果由谁消费。这是伪逐行，不因八项标题齐全或整课调用链正确而通过。代码前准备、代码中注释、整段功能描述、通用名词释义、作者自评与后章均不能代替当前正文；不能为避开难行缩掉必需源码。展示编号与原行分清，新增教学注释不改变原行定位。

例如条件为 `!isThinking`，正文须解释 `isThinking` 的真/假、`!` 取反与谁更新值，不能偷换成“没有思考文本”。数组/集合结论沿真实运算、原始与中间集合及拼接次序推演，局部有序不自动证明合并后全局有序，不从架构意图推出结果。一个生成方法若承接提示构建、渲染、请求、模型同步与回退，这些属于本课职责就完整展示并解释，不能只链接方法名；明确拆课时只声明接口边界与具体后课，不声称该机制已讲完。

随后按实际复杂度用“这一段怎样运行/边界与失败”“机制与设计判断”“怎么用、上下游与接入”等自然小节收拢。把同一输入代入刚讲语句，显示中间值、条件、返回和副作用；重要异常/回退在发生处讲停止点、残留状态和消费者结果。不存在失败不造；传播未查清就查必要调用处或准确留未覆盖边界，不声称已经完整解释。

设计判断从本问题的约束推导实现，比较具体可行替代及失败代价。回到真实调用表达式解释传参/结果消费与下一个符号；可插入点给真实实现或另标教学示意，追创建、扫描/收集/登记、查找与触发，说明新增必须同步哪些位置、漏接怎样表现。配置/纯数据追读取和生效，不硬套插件。此处完成本单元的局部用法，第六章深挖共同机制，第七章拼成完整回放，第八章综合跨单元修改。跨章可回指已充分教过的细节，但须在当前单元说明其如何作用于本次输入和行为；不能让第六、七、八章代替当前单元的机制、真实调用、局部演算或实际接入。

### 执行机制与数据要讲到哪里

沿具体表达式追生产值→创建/注册→中间适配与转交→调用/回调→实际消费者：谁持有值或函数、哪一句把它交给下一方、消费者怎样收到本次值。角色名和箭头用于导航，正文补齐真实交接，不能用一个“订阅者/适配层”跳过中间代码。区分声明支持的分支与当前实现可到达的路径：处理函数存在不证明当前有生产者，须核发送/触发及接线；未找到则准确留未知或说明已核范围内没有生产路径，不补想象中的隐藏连接。再区分同步步骤、异步等待与恢复、类型声明与运行行为、内存状态与持久化。`async` 声明不证明调用方 `await`，调用方没 `await` 也不证明内部没有等待；分别读调用表达式、返回接收、Promise 链与内部等待。回调中 return 和外层返回各指向哪个消费者，不能混为一谈。

“框架自动”展开是谁、何时、根据项目哪个注册/扫描/启动点做哪几步。import 不自动等于创建或注册：Java 的 import 用于名称解析；JavaScript/TypeScript 运行时导入可能执行模块顶层初始化，类型专用导入须区分。生成构造器/getter/builder 查真实工具声明，不编成手写实现。状态改变到重新渲染、Effect（副作用处理）或回调，解释实际触发机制和条件。穿透到足以解释本课行为、取舍与重要失效模式，不无限扩成运行时手册。

贯穿数据具体且稳定：字段、字符串、数组顺序、布尔值和中间对象。断言具体值、为空或默认行为时，沿真实来源追到本次消费者：按当前语言与实际机制核显式初始化、构造/工厂/基类、绑定或覆盖顺序及此前赋值，不把局部未赋值、名称或通用零值规则当依据；只追决定当前断言的必要来源，不要求每个变量全生命周期报告，不重核未受影响且已有有效证据的充分正文；缺证据就查必要直接来源或留未知。参数简写或等价表示须标为教学示意，不能冒充真实调用表达式。假设数值标为教学例，之后沿用，静态推演不冒充日志。Why/替代方案用当前场景比较，例如省登记导致哪种输入找不到实现，而非“解耦/易维护”口号。最小等价实现标“教学示意，非项目原文”，说明省略的生产边界；不声称运行过，不强制每课另写框架。

源码、框架和底层的讲法须帮助读者作开发与架构判断：从当前问题推导实现思路，展开机制、设计约束、可行替代、边界和具体失败；有真实历史再讲演进，无历史则将未来改法明确标为设计推演。其他章节也以场景、因果、例子和判断依据展开，不能成为 API 辞典或几句章首概要。零基础铺垫与工程深度同时保留，不以高级名词代替深入。

## 官方资料如何进入教学

先读构建清单、锁文件/依赖声明及实际 import 来源，核适用版本；动态范围不是锁定版本。普通官方API/语言规则默认引用适用版本的符号或章节入口，不为每次提API附源码行锚；正文实际展示外部原码时，才从同一真实raw缓冲取得切片、原行与URL，不用网页抽取显示行号。实际读维护者相关官方章节，必要时查依赖源码，以自己的话教**规则 → 机制 → 本项目具体语句映射 → 适用限制 → 直接章节链接**。这不免除下段决定框架保证所需最小源码及实际值教学，不能让读者自己查链接才懂。第五章所需规则在介入前讲，第六章综合深挖。

访问不到或版本未确认，准确说明已核范围与未知，不用新版规则为旧依赖背书。自动上下文、包装、回调、事务或重试等保证若决定本课结论，第六章须展示并教清适用版本中决定该保证的最小入口、条件判断、包装或分派源码，将本项目真实注册及调用表达式代入条件，沿实际可达路径推导保证是否成立；不能只断言“本项目注册满足条件”。注册本身不证明已包装，通用文档的简化描述不保证所有接入路径；仅查决定当前保证的实现，不要求所有API内部。源码不可访问或条件未证实时，以已核文档契约说明条件，并精确限定当前结论及未知，不编造源码或保证，也不阻断其他已具证据的教学。纯语言概念采用适用官方规范和真实项目语句，不强塞框架源码。通用文档不证明项目已注册/运行，不上传私人源码。链接不仅可打开，目标内容也须支持相邻断言：React 章节不能证明 Zustand，Zustand 不能证明 Virtuoso；本地锚点也核实际段落含义，不只验文件存在/行号在界内。

源码事实、官方规则、静态推断、假设例、真实观察和未知分清。课首说明整体证据范围，真正依赖未证实条件的断言旁限定，不每段重复同一句“未实测”。静态发送调用不能写成浏览器已收到，结尾免责也不能修正正文必然断言。作者动机无直接证据标推断。外部检索仅公开技术名/版本，不上传私人源码、标识或学习记录，不长篇复制版权文字。

## 返修保留教学内容

先有可恢复修前版本：可靠历史够用，无历史才留一次快照。修错、去实质重复和重组可以直接做，但原正确必要的概念/语法/机制、完整源段、具体值链、原因、正常/失败示例和官方映射须保留或已迁到可读目的位置。本课必要解释不能被“后面再讲”替代。无完整历史如实说明核对范围。

补缺时重组受影响单元，把问题、输入、源码和推导放回各自小节；新增总述与原逐组正文若在解释同一事实，合并到承担该教学任务的位置，其余只作必要导航或回指。保留正确源码和必要解释，去实质重复说明保留位置或迁移去向，不缩成用途摘要。局部修后只复读改动及影响上下游，同时核补文与已有解释是否重复；广泛重写、源范围大变或影响不明才再全文通读。简记具体缺陷、修复位置、删改原因与真实未核项，不造逐段矩阵、教材 hash 或词数/章节数指标。

## 教学就绪检查：何时可以提问

带答案复习是阅读材料，不是能力测验。正式预测/Quiz（测验）/复述前确认：前置已在实际交付教材/聊天充分解释，提供必要可读片段和上下文，用户愿意尝试；prepared、只提名称和假定读过都不够。问题诊断已教因果/修改影响，不让猜陌生字段成为推进门票。缺前置先讲，清旧 awaiting，`next_action=TEACH`；每轮不必测，能力 waiting 仍可继续教材。

“不会回答/一头雾水”先查漏讲或错序，保存原因/返回点，补缺而非换更小陌生题。只有已教后真实独立错误才记 gap。练习可从完整示范→愿意时带提示同类小步→就绪后独立变式→后续小实现，按真实表现减少支持。带提示成功不能称独立，也不替代最终 Mini Version；不代写用户复述。

## 首次需要时补齐阅读与操作基础

用当前真实文件解释仓库、项目根、目录/扩展名、相对路径、原行和符号，区分定义/调用、原文/新增教学注释。读者可自愿翻源码，不依赖其补正文。需操作时分清源码和终端命令，按实际系统/工具说明工作目录、参数/占位值、输出位置和相关报错定位，不默认会终端，也不强制安装才能只读学习。

## 发送前单轮交付自检

按 [写作入口](write-lesson.md#整节流程与保存顺序) 完成一次内容审读，实际覆盖每章及每个行为单元的全部适用职责，同时独立判断：**源码保真与知识事实**（源段/版本/条件/值链/官方映射真）与**教学展开**（必需概念在先、每个单元的八项职责充分、机制和例子能理解）。少数难点成功或全链正确不能推定其他单元合格；少量记录不等于少量核查。审核者懂而正文没教仍是缺漏，指出缺哪小节任务并修正文，标题、有效链接、篇幅和报告不能证明质量。

完整稿补缺、必要 V0/保存/索引成功可 ready/self_review 并 delivered，真实独立审读范围才 validated；未完整/仍缺必要教学留 draft/prepared。有限静态试用不能替代用户明确要求的验收，也不证明模型长期稳定或真实学习效果。交付与阅读均不提高 mastery，能力看真实学习者证据。默认聊天只主题、范围与链接，问题直接充分答疑。

## 知识桥梁、自由提问与实验

当前必要知识先教，真实阻塞/已证实误解进 KNOWLEDGE_DETOUR（知识绕行），按 [knowledge 模板](../assets/templates/knowledge.md) 保存白话、当前用途、深度、例子/陷阱和返回点；不把默认未知当失败。补齐后回主链，原题重新检查就绪。

自由提问立即解惑，局部问题不硬套十章。实质教材缺漏同步修对应文章/索引/进度，即时澄清不必重写整课。明确转开发保存学习返回点并尊重请求。实验按 Prediction → Modification → Run → Observe → Explain 记真实预测、授权、基线、命令/退出码、观察与清理，参见 [review 模板](../assets/templates/review.md)。无预测不伪造，未运行不验收 required 实验。

保护用户改动，优先隔离演示与最小有效检查；学习调用不授权安装、付费 API、有副作用服务或生产修改。已有授权可继续，缺必要授权只澄清具体动作，独立只读教学继续。实验/能力门禁按 [评估协议](evaluation.md)，持久化按 [记忆协议](memory.md)，记录不挤掉教材正文。
