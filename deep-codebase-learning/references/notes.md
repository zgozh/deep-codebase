# 详细教材、路径与质量门禁

## 正式交付与聊天答疑

交付类型按 [SKILL入口](../SKILL.md#开始或继续) 判断：长期课程每节默认正式教材，包括S00全景/单主题首课，作者自选窄主题或拆课不免整节正文门禁。用户明确要求局部/单函数专题时只免整节总量，不免模板、适用解释深度和正常Note Quality Gate；聊天即时澄清及用户明确短总结/简短笔记尊重其交付选择，不自动升为正式课。

每节详细笔记是默认正式教学，而非聊天之后的摘要或可选补充。初学者只看本篇就能理解本节目标，前课链接供扩展回顾，不能代替本节必要含义；不能要求先读聊天、查原源码、自己消化术语或官方链接。当前必要前置就地讲清，前课只提名称/浅讲时本课补足。聊天完成后只说明主题、覆盖到哪里与可点击笔记路径，不主动复贴整课。

用户在聊天提问就直接解释到解决该问题，包括源码、术语、框架和调用关系；局部问题不自动扩成整节课。仅明确要求完整聊天课堂才采用聊天整课。答疑发现笔记实质遗漏/错误/歧义时修订对应段落、索引及受影响进度；笔记完整但需要即时澄清，直接回答、保存有价值学习事件即可。不让用户先答测验、确认理解或回复“继续”才能阅读。

编写方式默认单会话；可选委派的任务边界与主审要求见 [编写模式](authoring.md)。无论哪个模式，内容、证据和路径门禁相同。

## 每节交付、自动总结与能力验收

- **每节笔记**：本轮写一个因果目标的完整教材，不等 Topic/Stage 或 Quiz 通过。同课ID先写完整连贯初稿，再按完整章/真实5.x充分扩写，完整正文先持久存原文part；齐后按[原文装配](writing-io.md#原文part装配与发布)生成新candidate、审读后原字节发布唯一最终note，已有note先保完整raw/Git基线。初稿可未达成品量但留draft/prepared，不当普通交付或临时总结的成品。全部适用小节充分展开、累计实际通读并补齐必要解释、保存/V0/索引成功才 delivered；single 可记 ready/self_review，不以独审为门票。未完整或仍有必要解释缺口的稿留 draft/prepared。交付不证明用户读过或理解。
- **Topic 收束**：跨多节的机制闭环时整合关系与新增解释；小术语、trivial helper 或答疑增量并入已有文章，不每条消息重复生成教材。
- **学习闭环**：实际独立回答/实验发生后补真实个人理解、误解和能力变化，不代写“我的复述”。
- **Session Checkpoint**：用户结束、重要边界、切阶段或上下文紧张时保存当前位置、未解项与下一步，保证重要内容已落盘。固定单一会话也执行；不按固定轮数复制历史。
- **Stage 综合**：阶段教材可先完成并通过文章门禁；Stage 能力未验收仍 in_progress。全部 exit criteria 通过后进入 STAGE_SUMMARY，综合主链、跨主题关系与真实认知证据，两门通过才 complete。
- **Project 完成**：全系统覆盖、重要横向结构、实验与独立重建等门禁通过，生成项目总览与重建复盘，不因笔记写齐就完成。

Journal 是结构化过程，Notes 是从源码和真实历史重写的技术知识，不复制事件列表、原聊天或职责摘要。显式总结当前主题/阶段/会话立即整理实际范围，保留当前学习位置、有效返回点及待评估能力；按 [PERSIST一致性约定](memory.md#post-turn-learning-commit) 纠正受影响记录和 next_action 的过期描述，最新意图确需换下一步时保留原返回点与原因，不倒写旧课位置或提升能力。未验收阶段仍可有质量合格的文章，清楚列能力等待项。仅明确要求“不写文件、聊天简短总结”时尊重该交付选择。

## 中文内容分类与稳定 ID

默认结构，按真实阶段命名，不预设所有项目都有登录等模块：

```text
.codelearn/notes/
  索引.md
  S00-项目全景/
    S00-T01-项目问题与业务能力.md
    S00-T02-模块协作与系统边界.md
    S00-阶段总览.md
  S01-登录与权限/
    S01-T01-01-从输入到登录请求.md
    S01-T01-02-身份校验与页面返回.md
    S01-阶段总览.md
  会话/
    会话稳定ID-学习回顾.md
  项目总览.md
  重建复盘.md
```

目录用稳定 Stage ID + 该阶段主要内容的中文名称；课名用稳定 Topic ID，拆课加连续课号，后接具体中文目标。避免统一堆入 `主题/`。英文类名、函数、框架、源码路径在正文保留，路径仍相对项目根。显式其他命名偏好优先。只创建当前需要的目录，不造空课程树。

索引按阶段分组，列 Stage/Topic/课号、中文目标、相对可点击路径、起止范围、事件来源、quality/verification、未覆盖/下一课及验收等待项。Stage/state/journal/roadmap/review 中的机器路径相对项目根，Markdown 链接相对所在文章；层级改变时必须重算相对链接，不能只改文件名。

**已有目录迁移**：首次应用新模式先读实际索引与引用。保持稳定 ID、文章内容和能力证据，建立旧→新映射；优先迁移当前阶段涉及的文章，不为恢复全量改名历史。旧结构可暂时通过索引访问，后续触及时迁移。迁移前检查解析后的目标均在当前 `.codelearn/`、无逃逸软链接、不覆盖已存在目标。同步更新所有相关索引、Stage、state/focus_files/next_action、journal、roadmap、review、knowledge 及笔记互链；历史旧路径只作为明确的迁移出处保留，不留失效活动链接。回读映射与旧引用，验证相关 JSON 与本地 Markdown 目标后提交事件。目标冲突/文件占用则保留原文件与有效入口，报告具体未迁移项，不强删目录、不杀进程、不抹历史。

## 沿流程写作

按 [唯一教学交付合同及十章表](teaching.md#唯一教学交付合同)、[源码单元合同](teaching.md#第五章源码之前源码之中源码之后) 和 [写作骨架](../assets/templates/stage-note.md) 编写；课程选哪些业务/功能仍按仓库生成。写作循环、门禁与保存顺序见 [写作入口](write-lesson.md)，示范加载见 [示范入口](authoring.md#源码写法输入)，不在笔记协议重复内容清单。

完整课遵守 [SKILL整课交付硬约束](../SKILL.md#整课交付硬约束) 的正文门禁，不另设整课总字数目标；重要小节和代码后首次行为/机制语义组按唯一 [试行扩写基线](teaching.md#试行扩写基线重要小节要展开到什么程度) 的默认展开下限及窄例外成稿、同次审读，不按每个术语或括号凑量，定位导航、纯闭合不凑字。独立准确理解为准，足量仍须事实、因果、机制和具体例子充分准确，缺解释不能通过；不为短删解释，不为详细重复。大范围按完整因果目标拆连续中文小课，逐篇列起止范围、未覆盖部分和具体下一源码点，不暗示未写部分已经学过。个人问题、初始理解、纠正、Aha、实验/Quiz/restatement 在真实发生时嵌入相关步骤，保留来源事件；缺证据就标等待，不代写用户表现。

## 候选知识与证据边界

首写 `status=draft`、`verification=unverified`；实际核对后记录 `source_checked`，真实运行只在观察覆盖范围记 `runtime_checked`，源码变化记 `needs_revalidation`。保留 source revision/hash、source_valid、review_method、review_ref、checked_scope、unchecked_claims、事件范围与修订说明。

`status=ready` 表示教材经实际通读、必要修稿后可正式交付，single 记 `review_method=self_review`。`validated` 留给真实独立审读的明确范围，记实际审查者/方法；独审可选，不是 delivered 的前提，也不等于外部专家认证、实测或学习者能力。draft/prepared 的备课不能算充分已教；ready 教材也只有实际充分解释的范围才支持 explained coverage。所有字段是轻量文章说明，不增加 schema 必填项；历史 validated 不批量改写或洗白，触及时按实际方法/范围判断。

全文分清源码事实、官方规则、假设例子、静态推断、真实运行与未知；只有旧笔记/注释不能单独证明行为。源码 revision 与 dirty 相关文件指纹用于核来源变化，不作为教材质量证明。

## Note Quality Gate

交付前按 [写作入口](write-lesson.md) 逐单元写足并过正文门禁，再做一次内容审读，并按其 [返修保留规则](authoring.md#返修保留教学内容) 补缺；结果写入现有 [review](../assets/templates/review.md)，不另造门禁或报告。既有一次 V0 核本次实际成稿的正文门禁，按用户请求的交付类型核适用下限；不足或必要解释未补齐仍draft/prepared，不能ready/delivered，返回同稿具体缺讲章/单元继续扩写，不逐章等用户或循环计数。新稿量与解释须以本次实际正文为据，足量旧示例或自评不能顶替。质量状态按上节真实方法/范围记录，格式检查和保存不能证明内容充分或用户能力。

首篇正文前已有最低state与Stage，集中收尾只更新/提交已有记录；source_refs须对象数组，实际state按记忆协议作只读结构V0。源码正文用独立include从已核本地raw渲染，装配后最终note有全部真实源码和充分解释，不留未解析标记。当前写入/回读须按作者流程实际观测解释正文数量与原预算；必要V0的源码定位按 [写入传输](writing-io.md) 核引用上游行锚及同源内容，不能只查文件或页面存在。完成后更新中文目录、索引/互链及相关JSON；图遵循 [图表协议](diagrams.md)，记录实际检查或未测。给主题、真实范围与笔记入口，按 [记忆协议](memory.md#post-turn-learning-commit) 保存本轮实际变化。

## 最终 Deep Dive

综合系统目的/全栈拓扑、关键业务与数据生命周期、配置和运行约束、故障定位/修改影响、跨模块取舍、真实误解与领悟、已验证实验、知识/coverage 索引、学习者独立设计与原方案比较、Mini Version 产物及实际验证。可以链接详细阶段文章，但核心架构/主链可独立读懂，不只串链接。先通过同样质量门禁和项目能力验收才标完成，保留未解/版本边界。
