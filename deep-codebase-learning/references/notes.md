# 详细教材、路径与质量门禁

## 正式交付与聊天答疑

每节详细笔记是默认正式教学，而非聊天之后的摘要或可选补充。初学者只看本篇就能理解本节目标，前课链接供扩展回顾，不能代替本节必要含义；不能要求先读聊天、查原源码、自己消化术语或官方链接。当前必要前置就地讲清，前课只提名称/浅讲时本课补足。聊天完成后只说明主题、覆盖到哪里与可点击笔记路径，不主动复贴整课。

用户在聊天提问就直接解释到解决该问题，包括源码、术语、框架和调用关系；局部问题不自动扩成整节课。仅明确要求完整聊天课堂才采用聊天整课。答疑发现笔记实质遗漏/错误/歧义时修订对应段落、索引及受影响进度；笔记完整但需要即时澄清，直接回答、保存有价值学习事件即可。不让用户先答测验、确认理解或回复“继续”才能阅读。

编写方式默认单会话；可选委派的任务边界与主审要求见 [编写模式](authoring.md)。无论哪个模式，内容、证据和路径门禁相同。

## 每节交付、自动总结与能力验收

- **每节笔记**：本轮授课即编写一个因果目标的完整教材，不等 Topic/Stage 完成或 Quiz 通过。保存、回读、质量检查、V0 与索引成功后记 delivered，草稿是 prepared。交付不证明用户读过，更不证明理解。
- **Topic 收束**：跨多节的机制闭环时整合关系与新增解释；小术语、trivial helper 或答疑增量并入已有文章，不每条消息重复生成教材。
- **学习闭环**：实际独立回答/实验发生后补真实个人理解、误解和能力变化，不代写“我的复述”。
- **Session Checkpoint**：用户结束、重要边界、切阶段或上下文紧张时保存当前位置、未解项与下一步，保证重要内容已落盘。固定单一会话也执行；不按固定轮数复制历史。
- **Stage 综合**：阶段教材可先完成并通过文章门禁；Stage 能力未验收仍 in_progress。全部 exit criteria 通过后进入 STAGE_SUMMARY，综合主链、跨主题关系与真实认知证据，两门通过才 complete。
- **Project 完成**：全系统覆盖、重要横向结构、实验与独立重建等门禁通过，生成项目总览与重建复盘，不因笔记写齐就完成。

Journal 是结构化过程，Notes 是从源码和真实历史重写的技术知识，不复制事件列表、原聊天或职责摘要。显式总结当前主题/阶段/会话立即整理实际范围，保留原返回点/awaiting/next_action；未验收阶段仍可有质量合格的文章，清楚列能力等待项。仅明确要求“不写文件、聊天简短总结”时尊重该交付选择。

## 中文内容分类与稳定 ID

默认结构，按真实阶段命名，不预设所有项目都有登录等模块：

```text
.codelearn/notes/
  索引.md
  S00-项目全景/
    S00-T01-项目问题与业务能力.md
    S00-T02-模块协作与系统边界.md
    S00-阶段总览.md
  S01-登录与权限/
    S01-T01-01-从输入到登录请求.md
    S01-T01-02-身份校验与页面返回.md
    S01-阶段总览.md
  会话/
    会话稳定ID-学习回顾.md
  项目总览.md
  重建复盘.md
```

目录用稳定 Stage ID + 该阶段主要内容的中文名称；课名用稳定 Topic ID，拆课加连续课号，后接具体中文目标。避免统一堆入 `主题/`。英文类名、函数、框架、源码路径在正文保留，路径仍相对项目根。显式其他命名偏好优先。只创建当前需要的目录，不造空课程树。

索引按阶段分组，列 Stage/Topic/课号、中文目标、相对可点击路径、起止范围、事件来源、quality/verification、未覆盖/下一课及验收等待项。Stage/state/journal/roadmap/review 中的机器路径相对项目根，Markdown 链接相对所在文章；层级改变时必须重算相对链接，不能只改文件名。

**已有目录迁移**：首次应用新模式先读实际索引与引用。保持稳定 ID、文章内容和能力证据，建立旧→新映射；优先迁移当前阶段涉及的文章，不为恢复全量改名历史。旧结构可暂时通过索引访问，后续触及时迁移。迁移前检查解析后的目标均在当前 `.codelearn/`、无逃逸软链接、不覆盖已存在目标。同步更新所有相关索引、Stage、state/focus_files/next_action、journal、roadmap、review、knowledge 及笔记互链；历史旧路径只作为明确的迁移出处保留，不留失效活动链接。回读映射与旧引用，验证相关 JSON 与本地 Markdown 目标后提交事件。目标冲突/文件占用则保留原文件与有效入口，报告具体未迁移项，不强删目录、不杀进程、不抹历史。

## 沿流程写作

使用 [技术教材模板](../assets/templates/stage-note.md) 调整叙事，主线是一个具体业务场景，按因果和实际调用顺序推进。每一环紧邻写：当前问题 → 首次相关概念白话解释与具体例子 → 真实注释代码 → 谁何时执行、参数/状态/副作用/消费者 → 当前分支与接续。不要开头堆长词典，不把所有代码放前面、解释和官方资料放后面让读者拼接。

与 [唯一教学交付合同](teaching.md#唯一教学交付合同) 一致：实际读取源码，注明项目相对路径、类/函数/组件及真实原行号或可靠符号定位。源码摘录保持原语句，新增教学注释明示；重要导入/类型/参数/变量/条件/调用/返回/副作用逐行或语义小段解释，语法不允许注释时用紧邻原行解释。值从哪里来、注册与触发时机、数据/状态如何改变、结果由谁使用要能跟读。

调用不能停在“它负责发送/加载/显示”：沿实际调用者与被调用者追当前目标，确实只保留接口边界时说明输入输出、已知影响、未展开内部与后续课，不能跳过当前必需机制。框架/浏览器 API 在介入处说明提供什么、何时参与、项目怎样接入、随后调用/管理什么；配置沿读取者、优先级、何时生效与影响。深入到足以解释当前设计与关键失效模式，不展开整本语言/框架手册。

至少用一个输入→用户可见结果的具体例子串起状态、数据、URL（存在时）与返回。演算值明确是假设，不冒充实测。重要错误/拒绝/取消/重试/超时/回退按实际源码在对应步骤讲，项目不存在就不编造。涉及 Why/替代设计/trade-off 则给具体场景，作者动机无依据标推断。

官方文档能帮助说明当前框架/API/协议时必须实际读适用版本章节：白话具体规则 → 框架/协议机制 → 对应项目源码 → 能确认与不能证明的范围 → 直接章节链接和适用版本边界。内容在使用处消化，不只列标题/网址，不把通用规则当项目运行观察。版本/资料不可访问准确说明限制，不伪造读取；若当前理解依赖未核实规则，保持草稿/缩小交付范围或补查，不用 unknown 掩盖必要解释缺失。只搜索公开技术与版本，不上传私人代码/标识/学习回答。

篇幅无任意字数目标：独立准确理解为准，不为短删解释，不为详细重复。大范围按因果链或清晰边界拆连续中文小课，逐篇列起止范围、未覆盖部分和具体下一源码点，不暗示未写部分已经学过。个人问题、初始理解、纠正、Aha、实验/Quiz/restatement 在真实发生时嵌入相关步骤，保留来源事件；缺证据就标等待，不代写用户表现。

## 候选知识与证据边界

首写 `status=draft`、`verification=unverified`；实际核对后记录 `source_checked`，真实运行只在观察覆盖范围记 `runtime_checked`，源码变化记 `needs_revalidation`。保留 source revision/hash、source_valid、review_method、review_ref、checked_scope、unchecked_claims、事件范围与修订说明。

`status=validated` 表示文章质量检查通过，注明 tutor self-review 或真实独立审查者；不是绝对正确、全部实测或能力认证。单会话自检不能自称独立审查，主会话审查子 agent 稿是不同上下文的主审，也不等于外部专家认证。未取得用户证据不妨碍完整文章通过内容质量门禁，但 Stage 能力门禁仍 waiting。写出/阅读文章不增加任何 mastery level。

全文清楚区分：源码事实 code-confirmed、官方规则 documented、静态/设计推断 inferred、真实运行 runtime-confirmed、未知 unknown。只有旧笔记/注释/模型先前解释不能单独证明行为；恢复未知 verification 的旧文保守使用，修当前文时补元数据，不批量重置历史。

## Note Quality Gate

交付前在 `.codelearn/reviews/<稳定课ID>-note-quality.md` 按 [review 模板](../assets/templates/review.md) 记录以下十项 pass/fail/N/A、文章定位、理由、检查者/方法与真实范围。N/A 必须有本节实际不涉及的理由；关键解释缺失不能以 N/A 或未知逃避。

1. 首次影响理解的重要名词、缩写、框架 API、项目概念给准确正式名称/缩写全称与中文白话，解释是什么、为什么此处需要、代码关系和具体例子；不编项目名全称、不用陌生词定义新词。
2. 真实源码已读、路径/符号/原行定位准确，重要语句有紧邻逐行/语义注释，导入/类型/参数/返回/分支/副作用可跟读。
3. 调用者、被调用者、执行时机、参数来源、返回消费者与状态变化没有必要断点，包含 UI/调用方返回。
4. 框架和底层机制解释足够读懂当前代码，配置等沿实际消费者/生效链。
5. 贯穿流程的具体例子与实际重要失败分支充分，演算值和运行观察分开。
6. 有帮助的官方资料实际读过、具体规则已讲清并映射项目，直链及版本/证明边界明确。
7. 源码事实、官方规则、静态推断、运行验证、未知分开，注释、正文与示例相互一致。
8. 遮住所有聊天，初学者仍能只靠本节理解覆盖的源码与流程；必要概念不能推给原源码/未读材料。个人理解有真实来源，能力等待项明确。
9. 叙事连贯，概念、源码、解释、例子紧邻，不是词典/代码/链接拼图；篇幅合理，拆课有起止/未覆盖/接续。Why 与替代设计在相关时有依据。
10. 中文分类目录、稳定 ID、索引和进度/互链一致。V0 回读、Markdown 路径/锚点和相关 JSON 检查通过；图遵循 [Mermaid 协议](diagrams.md)，记录实际解析/渲染或未测项。

缺失则先修稿，查证仍不足就如实限缩覆盖范围、保留草稿并报告未完成，不能包装成完整交付。未运行不是错误，可明确静态边界；必要机制漏讲是错误，必须补。通过再 validated、索引登记 delivered 并执行 POST-TURN。文档 V0 不自动运行项目测试、构建或服务。最后聊天简短给主题、起止范围和可点击路径；答疑始终开放。

## 最终 Deep Dive

综合系统目的/全栈拓扑、关键业务与数据生命周期、配置和运行约束、故障定位/修改影响、跨模块取舍、真实误解与领悟、已验证实验、知识/coverage 索引、学习者独立设计与原方案比较、Mini Version 产物及实际验证。可以链接详细阶段文章，但核心架构/主链可独立读懂，不只串链接。先通过同样质量门禁和项目能力验收才标完成，保留未解/版本边界。
