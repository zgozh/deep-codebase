> 与 [单元示范](unit-example.md) 同源：摘自 `ragent-official`（Apache-2.0，许可见 [原文](licenses/ragent-Apache-2.0.txt)）的学习笔记 `.codelearn/notes/S00-项目全景/S00-T03-05-队列拒绝与消息增量.md`。这里**只留标题，不留正文**——6,776 行的长课压成一张表，用来看「一章该切几个单元、一个单元几个块」。

## 3. 每个单元内部的七个位置

25 个单元共用同一套 H4，顺序固定：

1. `#### 实际问题与实现思路`
2. `#### 架构位置、真实触发与输入准备`
3. `#### 源码定位与阅读准备`
4. `#### 4–5 连续源码与紧邻逐行推导`
5. `#### 同输入局部运行与实际重要失败`
6. `#### 机制与工程判断`
7. `#### 怎么用、上下游、接入与修改影响`

前三个位置（实际问题、架构位置与真实触发、源码定位与阅读准备）在源码之前，每个至少两段、200 字以上；第四个位置是「源码块 → 该块的逐组解释」交替，块 5–15 行；最后三个位置在源码之后，分别管局部运行与失败、机制与工程判断、怎么用与上下游。

## 4. 怎么用这张骨架

- 开一节前，先用第 2 节判断本节该切成几个单元：按真实符号或内聚职责，不按文件、不按章节数。
- 单元标题写成「谁在什么时候做什么，为什么是这个顺序」这种带因果的句子，不写成「XXX 方法解析」——第 2 节 25 个标题都是前者。
- 一个单元写完，拿第 3 节七个位置逐条点名；缺哪条补哪条，不要用「机制与工程判断」代替「同输入局部运行与实际失败」。
- 骨架不提供篇幅标准。**块该多厚只看 [实测基线](measured-baseline.md) 的分布，不看这份骨架的行数。**
