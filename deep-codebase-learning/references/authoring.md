# 单会话与可选委派编写

## 首次选择与所有权

默认 single：当前模型规划、写教材、实际通读与保存，完整合格教材可以正常 delivered。首次在学习项目使用时简短询问一次：“采用单会话编写，还是主会话规划审查、子 agent 编写教材？”使用可用文本选择工具，无工具则在首次交付回复询问；无答复仍 single，沉默不授权委派。已有明确选择沿用，存当前 stage/journal，切阶段继承，不新增必填 state 字段。

delegated 需要宿主支持且用户选择，可能增加耗时/资源，不保证更好。Skill 不固定模型/推理档位，不要求安装服务、MCP、CLI 或后台。主会话拥有路线、最新偏好、索引与共享学习状态；子作者只拥有指定一节稿件，不改 state/journal/mastery/coverage/其他稿或项目代码，不提交/部署/安装或做未授权实验。任务给稳定 ID、唯一中文稿路径、具体场景/目标、前课真实解释深度、必要源码/官方资料、起止符号、排除旁支和接续点，遵守 [教学合同](teaching.md#唯一教学交付合同)。同稿只一人写，移交后再编辑；默认一次一节，独立并行也须明确所有权/依赖。作者停止写稿并交还后才开始首次通读。有实质新状态才通信，优先宿主完成通知或有界等待；不频繁 poll/list，不每次等待后另列 agent 状态，轮询次数不能证明作者空闲。

## 写出、读懂并交付一节

恢复最新偏好、实际教材边界及源码身份，选择本节问题与主链；读真实源码及必要适用官方章节，按 [十章教材骨架](../assets/templates/stage-note.md) 写一份完整可读稿。当前作者上下文首次写完整课，或重大反馈/广泛重写前，全文读 [公开代表性功能主课](quality-example.md) 中当前主课，理解其完整功能深度、架构协作、使用现场、源码前/中/后分工和机制推导；不用同页全部历史局部片段作每轮前置。微型 helper 只供局部语法校准，不能按它的篇幅和系统范围写整课。示例的语言、版本和业务事实不是通用要求，按真实技术栈核实；已理解的未变示例复用。概念先短释再深入教，第六章深化机制，不接收延期前置。具体缺口随写随查，不等全仓精读，不另造资料汇编或审查稿；不能凭缓存猜源码。

开写前在已有当前 stage、稿件开头或委派任务放四行 brief，不另建备课文件：

- 本节因果目标与起止符号。
- 必追的具体值、调用和交接。
- 此节必要前置与适用版本规则。
- 明确留到后续的内部机制及返回点。

复用已读且未变的规范与证据，只读主链和必要直接依赖，先写可读稿再定点查证；不预读全仓或凭缓存猜源码。作者先定 frontmatter 等元数据，交还时冻结正文与元数据，审读期间不并行改同稿。通信优先宿主完成通知，有实质更新才发送消息，不把等待与 list 组合成重复轮询。

完整稿做一次内容审读：single 作者自查，delegated 主会话自身独立读稿。按 [十章表](teaching.md#唯一教学交付合同) 逐章核 **1–10 每章全部相关职责**，按 [源码单元合同](teaching.md#第五章源码之前源码之中源码之后) 逐个有行为单元核前、中、后实际展开，不以第六至八章补过第五章缺口。所有章都从初学者出发，核必要前置是否充分示范、叙述与推导深度、具体例子、定位和可读性，不能只给术语定义；第九章答案须有推导和正文回指，第十章须交代范围、未知、下一课及交付不等于掌握。真不适用说明具体原因，不虚构。

在同一次阅读中，只凭正文复演真实使用、架构协作、同值全链及正常/重要失败，再核源段原行/内容/版本、条件/值/状态/消费者与适用官方规则及链接支持。须靠审读者自己的经验补出的步骤就是缺漏；事实正确与教得充分分别成立，标题、长篇幅、注释和作者自报都不能代替。缺哪部分就定位修正文，按下文返修范围复读，不另起审查流程或工具。

在现有 [review](../assets/templates/review.md) 用少量真实正文定位和简短推导、缺口修复说明支持结论，尤其是最难概念、源码单元和重要失败；证据不能代替完整通读，也不大段复抄或造逐段矩阵。定位优先稳定章节/符号，必要时给准确局部行，不维护教材总字节/hash 作为品质或常规索引字段。必要内容未教完仍 draft；合格 single 记 ready/self_review，真实独审范围才可 validated，均不证明实测或用户能力。

收尾一次完成必要文档 V0：UTF-8 安全回读、围栏及相关链接/索引/JSON/指针，复用未受影响的有效检查。回读最终展示首尾防止补丁/过期交接混入。明确跳过应用检查时不运行；无应用改动不跑应用测试/构建/浏览器。通过后由主会话集中更新一次必要索引/state/stage/journal，再简短交付主题、范围和入口；有价值问答及中断仍及时保存，不等整稿完成。

## 返修保留教学内容

先读现有稿件基线并确认可恢复修前版本：可靠 Git 历史足够，无则留一个本地快照，不无限备份。按 [内容保留合同](teaching.md#返修保留教学内容) 修缺陷后读实际 diff，对照有效源码、准确教学注释、概念解释、例子和推导是否保留。格式检查不能证明内容保留；删错/重复给具体依据，迁移须目标已写好、引用有效、本节必需含义仍在。无完整旧稿则说清保留核对边界。不能为提速、去重或精简缩掉必要深度，也不能用工具自动摘要代替教材；需要多解释时写足，收无关旁支不收深度。

在同一 review 短记具体缺口、修复位置及必要正文依据；实质删改/迁移说明原因与正确必要解释的已写好去向，不另建逐段矩阵/hash 报告。同稿修后按缺口及其依赖范围复读改动和上下游，复用未受影响的有效证据；仅广泛重写、源码范围大变或影响不明才全文重读。不反复输出整篇 diff，不以缩字目标、KB 或章节数判断深度。delegated 返还同一作者具体位置/依据/目标，作者交稿后主会话复读相应范围；必要解释未补齐仍 draft，不能为交付好看编通过。

## 中断、记忆与写入故障

每个有价值互动及时按 [记忆协议](memory.md#post-turn-learning-commit) 保存实际变化，讨论或中断留最小 checkpoint，不等整课成功才保存。唯一主会话维护共享状态和 pending 恢复，不复制整篇教材到记忆。作者失败/超时时如实保存现稿/未完边界，结束任务并交还所有权后可 single 接手；恢复不依赖旧子会话。

Windows 中文显式 UTF-8，Python 检查用 `-X utf8`。补丁匹配失败刷新实际局部，换唯一短锚点或安全局部替换；传输/编码失败先换可靠文件工具/apply_patch，不原样重试长命令、不重新研究全项目。收尾用实际当前局部短锚点，集中写本次必要 projections，不为匹配失败重读整篇。必要源码与官方规则查证仍须完成，不能当作浪费删掉。回读成功前不声称已保存，依赖保存的跨 Topic 推进仍须等待保存成功。
