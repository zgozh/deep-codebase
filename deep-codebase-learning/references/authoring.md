# 单会话与可选委派编写

## 首次选择与持久偏好

默认 single：当前模型规划、写教材、作者自查、保存完整待独审可读稿。首次在这个学习项目使用时简短询问一次：“采用单会话编写，还是主会话规划审查、子 agent 编写教材？”用宿主可用文本选择工具；没有工具时在首次交付回复中询问。delegated 需要子 agent 支持，可能增加耗时/资源，不许诺必然提高质量。已有明确选择直接沿用；没有答复仍 single 完成首节，沉默不构成委派授权。

模式不是知识测验或授课门票。当前 stage 与 journal checkpoint 保存 mode=single/delegated、是否已询问、用户原意和环境限制；切阶段继承，不新增必填 state 字段。已有项目无记录也提供一次，保留进度。用户可切换，宿主不支持委派则说明并 single 继续，不自建服务/CLI/后台或要求安装。Skill 不固定模型、推理档位或 agent 数量。

## 作者所有权：完整初稿后定点查证

主会话拥有路线、偏好、因果目标和共享学习状态。已加载且版本/内容未变的 Skill、模板、相关章节与证据直接复用；新会话、上下文丢失或实际变更才重读必要部分，不靠缓存猜源码、不逐轮全量 hash。作者拥有本节唯一稿件，恢复真实边界、确定贯穿输入及段落骨架，只读主链和必要直接依赖，尽早写出一份完整可读初稿。来源与缺口简记同一 review/journal，初稿后定点查证，不生成冗余资料汇编。必要解释未查明仍保留 draft，提速不减少讲解深度。

返修已有教材前，先确认一份可恢复的实际修前版本：可靠已有历史足够；无历史则留一个本地修前快照并记路径/身份，不引入工具或无限备份。按 [内容保留合同](teaching.md#返修保留教学内容) 对照语义教学单元，只修明确缺陷，不能用整篇摘要替代详细教材。修前来源不完整须声明边界，不能假称已验证全部保留。

用户选择 delegated 才给子 agent 有界任务：稳定 Stage/Topic/课 ID、中文目录、唯一稿路径、前课实际解释深度、具体场景/输入、起止符号、必要前置、接续点、排除旁支、允许读取的源码/版本资料与 [教学合同](teaching.md#唯一教学交付合同)。子 agent 只写该稿，不改 state/journal/索引/mastery/coverage/其他稿件或项目代码，不提交/推送/部署/安装，不做未授权副作用实验，不将私人源码外传。默认一次一节；独立并行必须先明确各稿所有权与依赖，不能多人写共享状态。

## 冻结、独立主审与返修

1. 作者集中自查、修稿，自查只作辅助，不另写一套权威 G2 报告重复独审。冻结前定好顶部 frontmatter 的字段、顺序与行数，留出 status、reviewer、review_ref 等收尾字段；仍标 draft，未发生结果不预填 pass/validated。在同一 review 冻结两份实际身份：明确起止及编码的教学正文 hash/可取回原文的实际版本，以及完整 frontmatter 快照/hash/实际版本。正文 hash 排除顶部元数据，二者都须可核验；hash 固定用 SHA256，优先对明确起止的原始字节实算，记录字节边界、是否包含 BOM 与换行策略，复核用同法，不隐式转换 CRLF/LF。hash 只锁身份，不证明解释保留；dirty 文件不能仅以 HEAD 代替身份。冻结后停止编辑、交还所有权。
2. 首版由独立审核者在自己的上下文完整冷读一次，不接受作者自评代替阅读；按 [G0/G1/G2](notes.md#note-quality-gate) 写具体路径答案，再回源核事实。同一次冷读融入阅读体验检查：场景与因果顺序是否连贯、解释是否紧邻所依赖代码、是否变成术语墙或链接墙；不另加一轮阅读或报告。必要解释先修正文再填简短 review，流程产物不能挤掉完整教材。正常/重要失败做能验证本目标的一轮重放，证据有效时不因改状态或称“最终验收”再次全文检查。主会话审子稿自身读全文，不只挑关键片段。review 定位优先标题、代码符号、短引文和正文身份，物理笔记行号只作补充；源码原行必须严格对应内容。single 作者自查不能充当独审，无独审仍可提供完整待独审稿并继续下一节。
3. 审核者只写 review，不改作者稿；返修给具体缺陷、依据和目标。原作者取回所有权后局部修、重新冻结两份身份、停止编辑。正文变动使旧最终通过失效，继承未变证据前先确认旧 G1 真正覆盖本课必要语法/机制深度，旧 G2 值链通过不能代替。只有“全文读过”或几个已修点没有整体 G1 依据时，扩大到缺证据范围，不继承空结论。有效证据可沿用：复读改动、依赖/上下游、内容保留情况及受影响正常/重要失败场景，记新身份和沿用旧身份/范围。全文重写、广泛边界/源版本影响、影响不明或旧阅读证据不可用时全文重审；首版不能局部抽查，局部复核不能冒称新增的全文通过。
4. 语义审查通过后原位更新已有 status/reviewer/review_ref 等审核字段，不增删 header 行；记录元数据收尾前后身份/差异，不重算未变正文或重新全文重放。源码版本、边界等事实元数据改变仍复核 G0 及相关推论。主会话集中更新本课索引/state/stage/journal/review，按 [pending 恢复顺序](memory.md#post-turn-learning-commit) 提交；每个有价值问答和中断仍及时最小 checkpoint，不把全部保存拖到整课通过。作者自查、独审、源码/运行证据及能力分别记，两个 agent 不证明实测或掌握。

收尾执行一次批量 V0：UTF-8 安全回读、围栏实际开闭配对/内容边界（不能只数奇偶）、本地链接、源码行与内容锚、两份冻结身份、相关 JSON 及 current Stage/Topic、事件与 pending/指针一致性。证据范围未变不重复；最后只改 state 指针则只补受影响 JSON/指针核对，不再全验 Markdown。发现实际失败只修相关项后复核。没有应用改动不自动跑应用测试/构建/浏览器；用户明确跳过时遵守，教学深度不变。

最终回复简短给真实文件产出、覆盖范围、正式/待独审状态和剩余缺口，不编完成百分比/ETA。准备、完整初稿、冻结待审、定点返修各阶段报告已有产物；耗时过长先缩无关旁支，保留必要解释深度。聊天答疑直接处理，实质缺漏返修受影响稿件，不让答疑等整课重编。

## 中断与写入故障

作者失败/超时/宿主限制时保存实际稿与未完成边界，不伪造完成。single 接手前结束原任务并明确交还所有权。恢复依靠源码、稿件/review 与 next_action，不依赖旧子会话；独审 waiting 不是继续教学的阻塞。待独审稿登记为 prepared，既可读也不能冒称正式 delivered 或掌握。

补丁一次匹配失败就刷新实际局部内容，改用唯一短锚点或保留用户差异的安全局部替换，不原样重试长补丁、不重做分析或全读项目。传输/编码失败先修方式：直接文件工具/apply_patch，PowerShell 显式 UTF-8、Python 检查用 `-X utf8`，避免长 Windows 启动参数、含 Markdown 的 JavaScript 模板字符串或不支持的编码 API。启动失败未改文件，保留已有成果；回读成功前不声称已保存。中文分类与迁移见 [笔记协议](notes.md)。
